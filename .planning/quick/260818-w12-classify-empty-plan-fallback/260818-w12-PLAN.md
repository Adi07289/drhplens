# Quick Task 260818-w12: Fix live classifier returning empty plans

## Problem

On the Streamlit-Cloud deploy, valid factual questions were being answered with the
"couldn't find it" educational refusal. Reported symptom: *"the live classifier is
returning empty plans."*

## Root cause (systematic-debugging, reproduced)

`agent/nodes/classify.py::run()` had a total-failure branch:

```python
except Exception:
    plan = []   # treats an LLM INFRA failure identically to a deliberate out-of-scope refusal
```

An empty `tool_plan` makes `agent/supervisor.py::route()` skip every tool and go straight
to `synthesize`, whose Branch 4 emits `_educational_refusal()`. So whenever the classify
LLM hop **errored or timed out** (Groq gpt-oss transient on the deploy), the user's valid
question was silently dropped to a refusal.

Evidence:
- Locally the classify hop **never** emits an empty plan for a valid question: **0/30**
  across 10 real DRHP questions × 3 runs, both `gpt-oss-20b`/`120b`. (An early
  `max_tokens=256` truncation hypothesis was **disproven** — the raw call returns
  `finish_reason='stop'` with valid JSON.)
- Therefore the deploy's empty-plans necessarily arrive through the `except` branch — the
  classify call is failing on the deploy, and that infra failure was being converted into
  an out-of-scope refusal. The exception was swallowed with **zero signal**, which is why
  it was invisible.
- Forcing `_llm_classify` to raise reproduces `tool_plan=[] → route='synthesize' → refusal`.

## Fix (defense-in-depth, minimal)

`agent/nodes/classify.py`:
1. New module constant `DEFAULT_TOOL = "drhp_rag"` (the safe route when routing is uncertain).
2. `except Exception` branch → **log** (`logger.warning(..., exc_info=True)`) so the
   deploy transient is diagnosable, then degrade to `plan = [DEFAULT_TOOL]` (attempt
   document Q&A) instead of `[]`.
3. In-scope, non-advice decision that clamps to **no valid tool** → also default to
   `[DEFAULT_TOOL]` (incoherent-but-valid ⇒ answer from the document, don't drop it).
4. **Unchanged:** the deliberate advice / out-of-scope path still returns `[]` → refusal.

Safe because the `drhp_rag` subgraph's own `gate1_check` / `scrub` / `cite_check` guards
still apply, so even an advice/jailbreak input that hits the failure path can't leak.
