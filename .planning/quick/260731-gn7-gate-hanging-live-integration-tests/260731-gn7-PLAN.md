# Quick Task 260731-gn7: Gate the hanging live integration tests behind explicit CLI flags

## Problem (isolated 2026-07-31)

Before `/gsd-ship`, the full pytest suite could wedge >2 min under `.env`. Root cause,
confirmed empirically this session:

- The **deepeval pytest plugin (and the langfuse SDK) auto-load `.env`** at session
  start. So gating live tests on **env-var presence** never actually gates — stripping
  `QDRANT_URL`/`GEMINI_API_KEY` from the shell did **not** stop the tests (they still ran
  live for 72 s). Any test gated by "env var present" is effectively **always live**
  whenever `.env` exists on disk — exactly the condition on a dev box, `/gsd-ship`, and CI.
- **Primary culprit — `tests/integration/test_agent_e2e.py`**: 5 tests gated only by
  `_MISSING` env check → run live Qdrant + Gemini graph invokes. Measured **72.17 s** with
  only 3/5 running (2 skipped for data reasons); `test_gold_set_smoke_subset` alone is
  3 sequential live invokes → full gold set clears 2 min. pytest-timeout is `method=signal`
  (per-test only) and tenacity retries stall past it.
- **Secondary — `tests/integration/test_langfuse_trace.py`**: `test_langfuse_client_
  initialized_when_keys_present` + `test_every_node_writes_a_span_with_claim_ids` gated only
  by `LANGFUSE_PUBLIC_KEY` presence → construct a real client → **~15 s `atexit` flush** to
  `cloud.langfuse.com` at teardown (uncovered by the per-test signal timeout). Observed
  wall 17.46 s vs 2.24 s test time.

Everything else is already safe: NSE/yfinance tests need `NSE_LIVE_SMOKE=1`; Qdrant/2nd-IPO
ingest tests are `xfail(run=False)`; `test_drhp_prompt_injection.py` is fully mocked; the
langfuse **live-attach** test already correctly requires `--run-langfuse`.

## Fix

Use the flags **already defined** in `tests/conftest.py` (`--run-eval`, `--run-langfuse`)
— the repo's established live-opt-in pattern (mirrors `NSE_LIVE_SMOKE` and the existing
`test_emit_enriched_trace_live_attach` guard). Explicit CLI flags are the only gate the
`.env` auto-load cannot defeat.

### Task 1 — `tests/integration/test_agent_e2e.py`
- **files:** `tests/integration/test_agent_e2e.py`
- **action:** Add an `autouse=True` module fixture `_require_run_eval_flag(request)` that
  `pytest.skip(...)`s unless `request.config.getoption("--run-eval")`. Keep the existing
  `_MISSING`/`xfail(run=False)` block as a secondary guard for the flag-on-but-no-creds case.
- **verify:** Under `.env` without `--run-eval`, all 5 tests SKIP at setup (no live call);
  with `--run-eval` they collect/activate.
- **done:** No live Qdrant/Gemini call on a bare `pytest` run.

### Task 2 — `tests/integration/test_langfuse_trace.py`
- **files:** `tests/integration/test_langfuse_trace.py`
- **action:** Add a `request` param + `if not request.config.getoption("--run-langfuse"):
  pytest.skip(...)` guard to `test_langfuse_client_initialized_when_keys_present` and
  `test_every_node_writes_a_span_with_claim_ids`, mirroring `test_emit_enriched_trace_live_attach`.
  Keep the `@_langfuse_skip` env marker (defense in depth). Fully-mocked and `classify_*`
  tests are untouched.
- **verify:** Under `.env` without `--run-langfuse`, those 2 tests SKIP and no ~15 s
  teardown flush occurs (wall ≈ test time); with `--run-langfuse` they activate.
- **done:** No real Langfuse client constructed / no cloud flush on the default path.

## Verification (quota-free — do NOT run the live agent)
1. `pytest tests/integration/test_agent_e2e.py tests/integration/test_langfuse_trace.py -v`
   under `.env` **without** flags → e2e all SKIPPED, langfuse 2 SKIPPED, rest pass; wall time
   a few seconds (no 15 s teardown, no 72 s live run).
2. Same two files `--collect-only --run-eval --run-langfuse` → previously-live tests are
   collected/active (collect-only never executes them → no live calls, no quota spend).
3. `pytest --collect-only -q` whole suite → no collection errors (syntax/fixtures intact).
