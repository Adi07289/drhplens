**Gathered:** 2026-08-04

<domain>
## Phase Boundary

Phase 6.3 (alias "6c") is the final phase before public launch. Two pillars:

1. **Agent orchestration upgrade (P8).** Turn today's single-tool, near-linear cited-Q&A `StateGraph` into a **full multi-tool LangGraph agent**: a bounded supervisor routes across read-only tools, fuses their outputs into one cited answer, and is hardened against infinite loops (TTL + semantic call dedup) and stress-tested against weird/adversarial user queries.

2. **Launch gate.** The P1 SEBI compliance checkpoint + the **OPS-02 public deploy** (deferred here all the way from Phase 1) + closing the 4 disclosed 6.1 production-stamp follow-ups.

No new v1 requirements — the phase is success-criterion-driven (ROADMAP 6.3 SC-1). Everything the tools read (peer / forecast / red-flag / GMP records + their Pydantic schemas) **already exists** as committed artifacts; 6.3 wires them to the agent, it does not build new pipelines.

**Scope guardrail:** discussion clarifies HOW to orchestrate + launch what's already scoped. New capabilities (esp. **cross-IPO / multi-IPO compare = deferred idea E3**) stay out — tools remain single-IPO-scoped.

</domain>

## Implementation Decisions

*(Captured in discussion 2026-08-04. These are implementation-HOW decisions; the phase boundary + cross-cutting invariants are locked upstream in ROADMAP.md / PITFALLS.md.)*

### Agent tool surface & graph shape (P8 orchestration)
- **D-01 — Full hybrid tool surface.** The agent exposes **all four** capabilities as agent-callable **read-only** tools: DRHP-RAG (existing) + `query_redflags`/financials + `query_peers` + `query_forecast`. GMP is folded in read-only alongside the forecast (see D-04). Rationale: matches the locked "hybrid agentic architecture" vision + ROADMAP "full multi-tool"; the data and `agent/*_schema.py` schemas are already committed. Trade accepted: this is the largest supervisor stress-test surface.
- **D-02 — Supervisor WRAPS the existing graph (does not replace it).** The current 10-node cite-Q&A `StateGraph` becomes the **"DRHP-RAG" sub-agent, unchanged**; the new supervisor sits above it and the other three tools are sibling nodes; a synthesis/emit step re-applies the **same scrub + compliance + cite-check** to tool outputs. Rationale: preserves every existing invariant (P5 cite-check, P1 compliance, gate1, scrub-retry) and its passing test suite. Explicitly NOT a flat "replace" rebuild and NOT two side-by-side code paths.
- **D-03 — Fuse into one cited answer.** For queries spanning capabilities, the supervisor may call multiple tools and a **synthesis node fuses** DRHP text + peer table + forecast band into ONE answer. **Every claim/number carries provenance to its committed-artifact source** and passes the same scrub + cite-check. This is the project core value ("fuse what the document says with how comparable IPOs behaved"). Implication for planner: extend cite-check so tool-derived numbers validate against the tool's source record (not only DRHP spans).
- **D-04 — GMP gap-signal surfaces in chat.** When the chat agent answers a pricing/forecast question, it includes the **GMP-vs-model gap** ("GMP says X; GMP-free model says Y; gap is Z") with the same caveat as the snapshot forecast block (GMP-03). **GMP stays hard-isolated — read-only display, never a model feature** (GMP-01/02, P4 invariant preserved).
- **D-05 — Bounded routing: LLM-classify + deterministic guardrails.** The supervisor uses **one bounded LLM classification hop** to propose the tool set, then a **deterministic allow-list + budget clamps enforce** it (can't invent tools, can't exceed the hop budget). Honors the locked "bounded state machine, NOT freeform ReAct" constraint. NOT a soft LLM-only router, NOT pure keyword rules.

### P8 loop-safety & weird-query handling
- **D-06 — Belt-and-suspenders (two mechanisms).** (1) A **hard deterministic loop bound** = max supervisor-hops + max total tool-calls + a **wall-clock backstop** (extends the existing `MAX_REGENERATE_ATTEMPTS=1` pattern in `agent/policies.py`) — this is the real P8 guard. (2) A **semantic-similarity tool-RESULT cache with a TTL that spans runs**, serving both within-run loop-tightening AND free-tier-quota / P19 demo-safety. The loop bound is the counter, not merely "cache hit".
- **D-07 — Stress-test covers all four weird-query categories.** The committed suite MUST cover: (a) **compliance-bait / advice-seeking** ("should I buy/subscribe?", "target price?") → the no-advice posture fires (banned-token scrubber + educational refusal), never answered as advice [P1 launch-critical]; (b) **prompt-injection / jailbreak** ("ignore instructions", "reveal system prompt", "drop the disclaimer") → posture + disclaimer hold, no leak, no persona break; (c) **off-topic / gibberish / empty / extremely-long** → graceful out-of-scope refusal, no tool thrash, no infinite retrieval, no crash; (d) **cross-IPO + fabricated-precision bait** → single-IPO redirect (E3 deferred), no loop; "not disclosed" instead of fabricated precision (numeric-faithfulness invariant).
- **D-08 — Honest partial on any failure.** On a single-tool error/abstain (e.g. forecaster has no band for this IPO) OR a hard budget-trip: **return whatever grounded + cited content exists so far, explicitly labelled incomplete** ("ran out of steps before finishing — here's what I found"); refuse ONLY when nothing grounded. **Never fabricate the missing part.** Note: this applies even to the budget-trip path (max user value + transparency was the explicit preference over a conservative clean-refuse).
- **D-09 — Stress-test = committed pytest suite that gates deploy.** Each of the four categories → test cases with **deterministic assertions** (no banned tokens emitted, disclaimer present, no system-prompt leak, hop-budget respected, single-IPO scope). Runs offline (deterministic checks need no live LLM). It is a **portfolio artifact + regression guard** and **gates deploy**, pairing with the CI gate lane (D-14).

### SEBI legal-review gate (P1 final launch gate)
- **D-10 — Honest self-audit doc only (no false "legal review" claim).** Deliver a committed **`compliance/SEBI-REVIEW.md`** — an honestly-labelled **self-audit**, human-reviewed, enumerating the RIA-scope boundary + disclaimer coverage + banned-token enforcement + no-personalization/no-fees. It is **NOT** a lawyer sign-off and must not be described as one (honesty invariant is load-bearing). **No NEW automated enforcement gate** is added; the doc **references existing enforcement** (the `compliance/scrubber.py` import-time assertion, the banned-token patterns, and the new D-09 stress-test suite).
- **D-11 — Full re-audit scope, including new 6.3 surfaces.** The self-audit covers the existing Phase-1 posture **AND** explicitly audits the new multi-tool agent behavior (fused answers + conversational forecast/peer/GMP framed as informational-not-advice) **AND** the public-deploy exposure (public users on live chat). The new conversational surfaces are exactly where advice can leak — they are the reason the gate exists now.

### Public launch shape (OPS-02)
- **D-12 — Live public chat with guards + graceful fallback.** The public deploy exposes the **real multi-tool agent**, protected by **per-session/IP rate-limiting + a hard daily cap aligned to the Gemini free-tier RPD + a graceful "demo quota reached — explore the read-only surfaces / recorded walkthrough" fallback** when exhausted. Recruiters can type a real question; abuse/quota is bounded. NOT a read-only-only demo, NOT a gated/BYO-key chat.
- **D-13 — Stay Streamlit for the v1 public launch.** Ship v1 on Streamlit + HF Spaces as locked; **Next.js migration stays a v2 concern** (STACK explicitly defers it). Resolves the flagged "Phase-5-exit re-evaluation gate" — decision recorded: no UI rewrite in 6.3.
- **D-14 — Close ALL FOUR production-stamp follow-ups (aim for the full production-ready stamp).** 6.3 targets the full stamp, not just the launch:
  - **WR-03** (requirements.txt ↔ pyproject sync) — pure-code, deploy-relevant, quick.
  - **CI gate lane** (GitHub Action running the release gate + the D-09 stress-test on PRs) — **requires repo SECRETS from the user**.
  - **Judge calibration** (≥50-example, ≥0.7 judge-vs-human correlation) — unblocks committing a real (non `-1`) faithfulness number — **requires HUMAN labels from the user + burns Gemini quota**.
  - **Gold-set span-tightening** (≤2–3pp `expected_sources`) — **requires a HUMAN reading the Swiggy DRHP PDF** to set real answer pages; **auto-substring-matching was already refused on honesty grounds (6.1) — do NOT re-run it.**

  ⚠ **Human-in-the-loop dependency (planner MUST sequence around this):** two of the four (judge calibration, gold-set span-tightening) **cannot be auto-completed by an executor** — they need the user's manual labelling / PDF reading; the CI lane needs user-provided secrets. Only WR-03 is executor-completable start-to-finish. Plan these as HITL checkpoints, and keep the honest `-1` "not measured" faithfulness surface until the ≥0.7 calibration actually passes (the 6.1 P10 guard).

### Claude's Discretion
- **Infra topology** — carried forward from the locked STACK / deployment plan: **HF Spaces (Streamlit) + Qdrant Cloud free (1GB) + Langfuse Cloud free + Gemini API** (`gemini-3.5-flash` → `gemini-3.1-flash-lite` fallback). Planner may confirm/adjust within the free-tier constraint.
- **P19 warm-keep mechanics** — pre-index the corpus, cache LLM/tool responses, cron pinger to keep the Space warm, offline demo video — standard P19 final-pass hygiene; planner's call on exact form.
- **Numeric budget values** — the actual hop count / total-tool-call cap / wall-clock ceiling / semantic-dedup similarity threshold / cache TTL are **calibration values** (Claude/planner discretion), tuned like the existing `agent/policies.py` constants; the *semantics* are locked in D-06.
- **Supervisor node internals, tool-node file layout, synthesis prompt phrasing, stress-test file structure** — planner/executor discretion, consistent with D-01…D-14.
- **Recorded-walkthrough / example-transcript form** for the quota-exhausted fallback (D-12) — planner's call.

<specifics>
## Specific Ideas

- **Honesty is the load-bearing thesis of the whole project** and dominates every 6.3 decision: the SEBI gate is honestly a *self-audit* not a lawyer review (D-10); failures return honest partials never fabrications (D-08); the faithfulness surface stays `-1` "not measured" until the ≥0.7 calibration truly passes (D-14); GMP stays display-only (D-04); fabricated-precision bait is a first-class stress category (D-07d).
- **"Full multi-tool" means fusion, not a tool menu** — the win is one cited answer weaving DRHP text + peers + forecast (D-03), which is the product's core value proposition.
- **The launch is genuinely public + interactive** (live chat, D-12) but must survive free-tier limits + abuse — guards + graceful degradation to the read-only surfaces are the mechanism.
- **6.3 is the "hold public launch" phase** — nothing ships publicly until the SEBI self-audit (D-10/D-11) + the deterministic stress-test gate (D-09) pass.
