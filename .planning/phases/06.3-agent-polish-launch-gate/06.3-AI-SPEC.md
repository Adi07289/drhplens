## 1. System Classification

**System Type:** Hybrid — a **bounded multi-tool LangGraph agent** that fuses DRHP-RAG document retrieval with structured read-only tool calls (peers / forecast / red-flags+financials / GMP) into a single cited answer. Not autonomous ReAct (bounded state machine, hard-stop invariant); not pure RAG (multi-tool fusion is the core value).

**Description:**
Phase 6.3 upgrades DRHPLens's existing single-tool cited-Q&A agent (`agent/graph.py`, a 10-node LangGraph `StateGraph` in production since Phase 1) into a full multi-tool agent. A **bounded supervisor wraps the existing graph unchanged** (it becomes the DRHP-RAG sub-agent, D-02); three new read-only tool nodes (`query_peers`, `query_forecast`, `query_redflags`/financials, with GMP folded read-only) sit as siblings and READ committed `data/*` artifacts (storage-is-the-integration-bus). A synthesis node **fuses** tool outputs into one answer where every claim and number carries provenance to its source artifact and passes the same banned-token scrubber + deterministic cite-check the existing graph uses (D-03). The audience is Indian retail investors (mobile-first, informational/educational only) + DS recruiters reviewing the portfolio. **"Good"** = a fused, honestly-cited answer that respects the SEBI no-advice posture under adversarial input, provably terminates (P8), and degrades to an honest partial (never a fabrication) when a tool fails or the budget trips.

**Critical Failure Modes:**
<!-- The 3-5 behaviors that absolutely cannot go wrong in this system -->
1. **Advice leakage under adversarial input** — the agent answers a "should I buy / target price?" query as investment advice, or a jailbreak strips the disclaimer / banned-token scrubber. This breaks the P1 SEBI RIA-scope boundary and is the launch-gate-critical failure (D-07a/b).
2. **Non-termination / unbounded loops** — the supervisor loops tools indefinitely or blows the free-tier quota (P8). The hard hop/tool-call + wall-clock bound MUST deterministically terminate every run (D-06).
3. **Fabricated fusion** — a fused multi-tool answer emits a number or claim that does not trace to its committed-artifact source (e.g. an LLM-paraphrased forecast band that drifts from `data/forecasts/*.json`, or a GMP value leaking into a model claim). Every fused number must pass provenance cite-check (D-03, D-04).
4. **Dishonest failure** — on a tool error/abstain or budget-trip the agent fabricates the missing part instead of returning an honest labelled partial / refusing when nothing is grounded (D-08).
5. **Fabricated precision** — the agent invents decimal precision or a "not disclosed" figure rather than honestly declining (numeric-faithfulness invariant, D-07d).

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Finance — Indian primary-market / IPO analysis. Decoding the DRHP/RHP (the 300–500-page SEBI prospectus) for retail investors and placing the issue in peer + historical-listing context. A SEBI-regulated adjacency: the product must sit *outside* the Research Analyst / Investment Adviser boundary, not inside it.

**User Population:** Two audiences with an asymmetry that sets the stakes.
- **Primary — Indian retail investors** (mobile-first, non-expert). Post-2021 demat-account boom, intense IPO-subscription frenzy, high hype-vulnerability; most never read the prospectus. **This user can act financially on the output** — apply / not-apply to an IPO with real money.
- **Secondary — DS/ML recruiter** reviewing the portfolio. Judges rigor, honesty, and eval discipline; **cannot** act financially. The public live-chat (D-12) means a recruiter can type a real question — so the same answer surface serves both, and must hold the retail-user stakes bar even when the recruiter is the one testing it.

**Stakes Level:** High on the financial axis, **Critical on the regulatory axis** — the launch gate exists because crossing the SEBI advice boundary is the failure that cannot ship (D-07a, D-10/D-11).

**Output Consequence:** A retail user reads a fused, cited answer and decides whether to **subscribe to an IPO — committing real capital** (ASBA blocks the application funds; hyped Indian IPOs list flat or below issue often enough that the downside is real). An answer that reads as a lean — "trades at a discount to peers, GMP is strong, margins improving" — can push a subscribe decision **and** expose the operator to SEBI unregistered-advice liability (the finfluencer-crackdown context). Downstream = real money moved + regulatory exposure. That dual consequence is why "informational, never advice" is a hard invariant, not a tagline.

### What Domain Experts Evaluate Against

<!-- Practitioner-language rubric ingredients for the eval-planner. What a SEBI-compliance-literate reviewer or an experienced IPO analyst would accept vs flag. -->

**Dimension: No-advice framing (informational, not prescriptive)**
- Good (expert accepts): Describes what the DRHP discloses and how comparable IPOs behaved, framed as *context*. No directional judgement, no subscribe/avoid conclusion, disclaimer present, zero banned prescriptive tokens.
- Bad (expert flags): Answers "should I subscribe?" with a lean; calls the issue over-/under-valued vs peers; gives a target / fair value; or steers to a subscribe/avoid action even without a banned word ("advice by implication").
- Stakes: **Critical**
- Source: SEBI (Research Analysts) Regs 2014 + (Investment Advisers) Regs 2013 — buy/sell/hold recommendations and price targets are RA-registered activity; the education-vs-advice line SEBI drew in the Jan-2025 finfluencer framework.

**Dimension: Forward-looking claims are hedged, never asserted**
- Good (expert accepts): The listing-day forecast is a *calibrated range with explicit uncertainty* and a coverage caveat — "range of how comparable IPOs behaved," not a prediction of this issue's price. Abstains honestly where history is insufficient.
- Bad (expert flags): An unhedged forward statement ("this will list at a premium"), a point estimate dressed as certainty, or anything that indirectly *suggests a future price*.
- Stakes: **Critical**
- Source: SEBI Jan-2025 finfluencer framework — unregistered persons must not make performance claims or indirectly suggest future prices; IPO-analyst prediction-humility norms.

**Dimension: Material-risk completeness (issuer-specific, not boilerplate)**
- Good (expert accepts): Surfaces the issuer-specific flags an analyst checks — related-party transactions (RPTs), promoter share pledging, promoter/holding cuts, contingent liabilities, auditor qualifications, litigation, use-of-proceeds concerns — grounded in the actual DRHP.
- Bad (expert flags): Passes generic risk-factor boilerplate off as issuer-specific, OR omits a disclosed RPT / promoter-pledge / going-concern flag the DRHP actually contains.
- Stakes: **High**
- Source: Indian IPO due-diligence practitioner norms; DRHP structure (Risk Factors, RPTs, Promoter Background, MD&A); the project's v2 Red-Flag Radar thesis.

**Dimension: Peer comparison is apples-to-apples**
- Good (expert accepts): Peer multiples compared like-for-like (same metric, comparable period, disclosed source), peer set justified and caveated.
- Bad (expert flags): Apples-to-oranges framing — trailing vs forward multiples mixed, non-comparable or survivorship-selected peers — presented as a clean "cheap/expensive vs peers" verdict.
- Stakes: **High**
- Source: Equity-analyst valuation norms; the hardcoded "overvalued/undervalued/fair value" banned-token posture.

**Dimension: Numeric faithfulness / no fabricated precision**
- Good (expert accepts): Every number traces to its committed-artifact source (DRHP span, peer record, forecast band); says "not disclosed" when the DRHP is silent; precision matches the source.
- Bad (expert flags): Invented decimal precision; a fabricated figure where the DRHP says nothing; or a table-extraction-noise number (wrong column / wrong period / hallucinated denominator) asserted as fact.
- Stakes: **Critical**
- Source: Financial-RAG production research — adjacent-column / temporal-misalignment errors are the *dominant* failure class, with ~22% estimated hallucination in one real financial deployment; DRHP financial-statement + RPT-table density.

**Dimension: GMP is context, never a signal**
- Good (expert accepts): Grey-market premium shown as read-only display context beside the model, explicitly caveated ("GMP says X; GMP-free model says Y; gap is Z"); never a predictor.
- Bad (expert flags): GMP presented as a subscribe signal, folded into a model claim, or used to imply the listing will pop.
- Stakes: **High**
- Source: Project GMP-isolation invariant (P4, D-04); SEBI finfluencer "no indirect future-price suggestion" line — GMP is unregulated grey-market sentiment.

### Known Failure Modes in This Domain

<!-- How failure manifests HERE specifically — not generic hallucination. -->

1. **Advice by implication (the launch-critical one).** The model never emits a banned word, so the scrubber passes, but frames the answer so the subscribe/avoid conclusion is unmistakable ("discount to peers + strong GMP + improving margins"). The *posture* is breached even though the token filter is clean — this is exactly why the compliance eval needs a judge, not just a regex.
2. **GMP anchoring.** Sentiment of the whole answer tilts toward the grey-market premium (a hype proxy), which is effectively an indirect future-price suggestion — the precise thing the finfluencer rules target.
3. **Survivorship-blind forecast / peer framing.** A listing-gain range or peer set drawn only from listed survivors understates downside; or an unhedged "IPOs like this tend to pop" narrative that reads as a prediction.
4. **Over-precise numbers from table-extraction noise.** DRHP financial statements + RPT tables are dense, merged-cell, multi-period; the model emits a confident figure from the adjacent column/period or a fabricated denominator, or invents decimal precision the DRHP never stated (the numeric-faithfulness invariant, D-07d).
5. **Boilerplate-risk laundering.** Regurgitating generic risk-factor boilerplate as if it were an issuer-specific red flag — or the inverse, burying a real disclosed RPT / pledge under generic text so the user never sees it.

### Regulatory / Compliance Context

> **Weighed heavily — this directly feeds the D-10/D-11 SEBI self-audit (`compliance/SEBI-REVIEW.md`).** The posture below is honest about what is verified vs what the self-audit must still confirm against the actual gazette/circular text. **None of this is legal advice, and D-10 is a self-audit, NOT a lawyer sign-off** — the honesty invariant is load-bearing here.

**The two regimes that define the boundary DRHPLens must stay OUTSIDE:**

- **SEBI (Investment Advisers) Regulations, 2013.** "Investment advice" = advice on buying/selling/dealing in securities or on an investment portfolio, given *for consideration* and *personalised* to a client's risk profile / suitability. RIA registration required. **DRHPLens stays outside via:** no personalisation (one generic informational surface, no client risk-profiling or suitability step), no fees / consideration, no portfolio construction.
- **SEBI (Research Analysts) Regulations, 2014** (last amended **December 16, 2024**). Regulates non-customised, security-specific **buy/sell/hold recommendations, price targets, and research reports** on securities. **DRHPLens stays outside via:** it emits no recommendation, no target / fair value, no subscribe/avoid verdict — enforced by the hardcoded banned-token scrubber (import-time assertion, TRUST-02/03 anchor).
- **The education-vs-advice line / finfluencer framework (SEBI, ~Jan 2025; via the SEBI (Intermediaries) Amendment Regulations, 2024, Section 16A).** SEBI explicitly *distinguishes education from advice*: unregistered persons must not make buy/sell calls, performance/return claims, or indirectly suggest future prices; registered intermediaries may not associate with unregistered advice-givers; a **three-month data lag** applies to educational use of *live* market data. **Relevance:** DRHPLens rides exactly this education/context line. It is naturally on the safe side of the data-lag rule (it uses public DRHP filings + *historical* listing data, not live tips), and the GMP-as-display-only + calibrated-range-not-a-price-call design are the mechanisms that keep it there.

**The hardcoded posture the self-audit maps onto (all already in the codebase):**
- Banned prescriptive-token scrubber — `compliance/banned_tokens.py` (buy, sell, subscribe, avoid, recommend, target, fair value, over-/undervalued, target price, accumulate, out-/underperform, bullish, bearish, book profits; morphological stems) enforced by `compliance/scrubber.py` with an import-time assertion.
- Single-source disclaimer copy — `compliance/disclaimer_text.py` `ANCHOR_COPY` on three surfaces (first-use modal + persistent footer + per-answer footer), including an AI / "large language models make mistakes" disclosure.
- No personalisation, no fees, no portfolio, single-IPO informational scope (E3 cross-IPO deferred).

**Honesty flags — regulatory claims I could NOT fully verify (load-bearing; the self-audit MUST close these against primary sources):**
1. I confirmed the RA Regs were *last amended Dec 16, 2024* and that a *Jan-2025 SEBI finfluencer framework* exists (Intermediaries Amendment 2024, Section 16A; SEBI action late Jan 2025) drawing the education-vs-advice line + three-month data lag. I did **not** independently verify the exact clause text, nor that every detail (e.g. the precise scope of the three-month lag) applies to a *non-registered, public-filing-based* tool like DRHPLens. The self-audit should cite the actual gazette/circular, not this section.
2. `compliance/disclaimer_text.py` cites "SEBI Jan-2025 RA requirements" for a ~10pt-equivalent minimum font and an "AI / large language models" disclosure. I could **not** independently confirm a specific SEBI mandate requiring an AI-model disclosure or that exact font size *for an unregistered informational tool*. SEBI did tighten standardised advertisement/disclaimer + prominence norms for RAs/IAs around 2024–25, but treat the AI-disclosure + 10pt specifics as a **prudent self-imposed posture** unless the self-audit locates the exact provision.
3. Whether DRHPLens's specific *fused-answer* behaviour falls entirely outside RA/IA scope is ultimately a **legal determination**. Nothing in this research substitutes for one; D-10 must remain honestly labelled a self-audit.

## 2. Framework Decision

**Selected Framework:** LangGraph (CONFIRMED — pre-locked, not reopened)

**Version:** 1.2.2 — pinned `langgraph>=1.2,<2` in both `requirements.txt` and `pyproject.toml`; verified installed at 1.2.2 in `.venv` (with `langchain_core 1.4.0`, `langgraph_checkpoint 4.1.1`).

**Rationale:**
LangGraph has been the agent orchestrator since Phase 1 and is in active production use — `agent/graph.py` is a compiled 10-node `StateGraph` today. Phase 6.3 does not select a framework; it extends the incumbent. Three properties make it the right primitive for this phase's work: (1) its **counter-bounded conditional-edge / zero-cycle** pattern (`MAX_REGENERATE_ATTEMPTS` in `agent/policies.py`) is exactly what the new P8 hop-budget + wall-clock backstop extends (D-06); (2) the compiled-graph model lets a **supervisor wrap the existing graph as a sub-agent unchanged** (D-02), preserving every existing cite-check / scrub / gate invariant and its passing test suite; (3) built-in checkpointing + bounded control keep the agent a **bounded state machine, NOT freeform ReAct** (a hard architecture invariant in CLAUDE.md + ROADMAP). It is OSS (no vendor lock-in) and free-tier compatible.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LlamaIndex Workflows | LangGraph is already the production orchestrator and provides the bounded-cycle + checkpointing control the D-06 loop-safety design depends on. LlamaIndex stays in its lane as the RAG ingestion/index layer, not the orchestrator. |
| Plain Python + asyncio | Loses built-in checkpointing, the counter-bounded-edge pattern the P8 guard reuses, and the recruiter-signal of "built on LangGraph"; would re-implement graph control by hand. Ruled out on production-incumbency + safety-tooling grounds. |
| Freeform ReAct agent (LangChain AgentExecutor) | Directly violates the "bounded state machine, NOT freeform ReAct" invariant — unbounded tool loops are the exact P8 failure mode this phase exists to prevent. |

**Vendor Lock-In Accepted:** No — LangGraph is OSS/self-hostable; the reasoning LLM (Gemini via `google-genai`) is swappable through the `GEMINI_MODELS` fallback chain in `agent/policies.py`; storage (Qdrant) and tracing (Langfuse) are already free-tier/self-host. Streamlit is v1; a Next.js/FastAPI split is a deliberately-deferred v2 concern (CONTEXT.md D-13).

### Entry Point Pattern
```python
# agent/supervisor.py — bounded supervisor WRAPS the existing DRHP-RAG graph (D-02).
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver
from agent.graph import build_graph
from agent.supervisor_state import SupervisorState        # SupervisorState(GraphState) — see §4
from agent.policies import MAX_SUPERVISOR_HOPS, MAX_TOOL_CALLS

# 1) Compile the existing 10-node graph WITHOUT its own checkpointer, so the parent's
#    checkpointer propagates into it (pitfall #2). Same GraphState keys ⇒ embed directly.
drhp_rag_subgraph = build_graph(checkpointer=None)

def classify(state: SupervisorState) -> SupervisorState:
    """ONE bounded LLM-classify hop → proposes a tool set; a deterministic
    allow-list clamps it so the LLM cannot invent tools (D-05). See §4b."""
    proposed = _llm_classify(state["question"])               # Instructor + Gemini
    allowed = {"drhp_rag", "query_peers", "query_forecast", "query_redflags"}
    plan = [t for t in proposed.tools if t in allowed]        # clamp
    return {**state, "tool_plan": plan, "hops": state.get("hops", 0) + 1}

def route(state: SupervisorState) -> str:
    """Deterministic budget guardrail (D-06): the counter trips BEFORE any framework
    limit. Over budget or plan empty ⇒ synthesize (which honest-partials, D-08)."""
    over_budget = (
        state.get("hops", 0) > MAX_SUPERVISOR_HOPS
        or state.get("tool_calls", 0) >= MAX_TOOL_CALLS
    )
    if over_budget or not state.get("tool_plan"):
        return "synthesize"
    return state["tool_plan"][0]                              # dispatch next pending tool

g = StateGraph(SupervisorState)
g.add_node("classify", classify)
g.add_node("drhp_rag", drhp_rag_subgraph)                    # ← compiled graph AS a node (D-02)
g.add_node("query_peers", query_peers_node)                 # plain read-only loaders (§4 Tool Use)
g.add_node("query_forecast", query_forecast_node)           # forecast + GMP read-only (D-04)
g.add_node("query_redflags", query_redflags_node)
g.add_node("synthesize", synthesize_node)                   # fuse + re-scrub + cite-check (D-03)

_ROUTE_MAP = {
    "drhp_rag": "drhp_rag", "query_peers": "query_peers",
    "query_forecast": "query_forecast", "query_redflags": "query_redflags",
    "synthesize": "synthesize",
}
g.add_edge(START, "classify")
g.add_conditional_edges("classify", route, _ROUTE_MAP)
# Each tool node pops itself from tool_plan + increments tool_calls, then re-enters the
# router. This is a COUNTER-bounded conditional edge, not a free LangGraph cycle — the
# exact zero-cycle pattern _route_scrub already uses.
for tool in ("drhp_rag", "query_peers", "query_forecast", "query_redflags"):
    g.add_conditional_edges(tool, route, _ROUTE_MAP)
g.add_edge("synthesize", END)

# recursion_limit is the LAST-RESORT crash backstop only (set ~2× the max legal hops);
# the explicit hops/tool_calls counter is the real P8 guard. GraphRecursionError is
# caught by the caller and converted to an honest partial (D-08), never surfaced as a crash.
supervisor = g.compile(checkpointer=SqliteSaver.from_conn_string("data/agent_cache.sqlite"))
```

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `StateGraph(State)` → `.compile(checkpointer=)` | Graph builder; compile returns an invokable Pregel graph | Both the supervisor and the existing DRHP-RAG graph are this |
| Compiled graph as a node — `add_node("drhp_rag", subgraph)` | Embeds a compiled graph as ONE node; shared state keys flow in/out automatically | D-02: wrap `agent/graph.py` **unchanged** as the DRHP-RAG sub-agent |
| `add_conditional_edges(src, fn, map)` | Deterministic routing on a pure Python function of state | The bounded router + the counter-bounded tool→router loop (extends `_route_scrub`) |
| `Command(update=, goto=)` | Combine a state update + control-flow jump in one node return | Optional alt to conditional edges for the dispatcher (`from langgraph.types import Command`) |
| `recursion_limit` / `GraphRecursionError` / `RemainingSteps` | Framework step budget (default 1000 super-steps) + raised error + managed counter | Belt-and-suspenders P8 crash backstop UNDER the explicit hop/tool counter (D-06) |
| Checkpointer (`MemorySaver`/`SqliteSaver`) + `thread_id` | Per-thread state persistence; required on every invoke once a saver is attached | SqliteSaver so the D-06 cache TTL spans runs; fresh `thread_id` per session |

### Common Pitfalls
1. **State-key collision between parent and subgraph.** The embedded DRHP-RAG graph reads/writes `GraphState` keys (`question`, `grounded_answer`, `refusal`, `regenerate_attempts`…). If `SupervisorState` reuses those same keys with a *different* meaning, the subgraph silently clobbers supervisor state and vice-versa. Fix: `SupervisorState` **extends** `GraphState` (a superset) so shared keys keep ONE meaning; keep supervisor-only keys (`hops`, `tool_calls`, `tool_plan`, `tool_results`) disjoint. If schemas ever genuinely differ, wrap the subgraph in a *function* node that transforms state in/out instead of embedding it directly.
2. **Checkpointer double-compile / non-propagation.** A compiled subgraph must NOT carry its own checkpointer when embedded — the parent's checkpointer propagates automatically. The existing `GRAPH = build_graph(MemorySaver())` singleton is for the standalone app; for the supervisor, call `build_graph(checkpointer=None)` so the parent `SqliteSaver` owns persistence. (The `build_graph(checkpointer=None)` signature already supports exactly this.)
3. **`recursion_limit` is the WRONG P8 guard.** It counts *every* super-step of the whole nested run (default 1000 — far too loose for a free-tier quota) and raises `GraphRecursionError`, i.e. a **crash**, not the honest-partial D-08 exit. Make the explicit `hops`/`tool_calls` counter routed to `synthesize` the real bound; set `recursion_limit` low (~2× max legal hops) purely as a crash backstop, catch it, and convert to an honest partial.
4. **Subgraph internals are invisible to a plain stream.** `supervisor.stream(...)` hides steps that run INSIDE the DRHP-RAG subgraph unless you pass `subgraphs=True` (then filter by namespace). If Streamlit progress or Langfuse enrichment needs per-tool events, stream with `subgraphs=True`; otherwise the nested tool-call counts (which `count_tool_calls` derives) under-report.
5. **`thread_id` is mandatory once a checkpointer is attached.** Both the existing graph (see `invoke_with_tracing`) and the supervisor require `config={"configurable": {"thread_id": ...}}` on every invoke or the graph crashes — this is what silently zeroed the numeric-faithfulness eval before. Key the D-06 cross-run cache by a *semantic hash of the tool call*, NOT by `thread_id`, so a fresh `thread_id` per session isolates conversation state while the cache persists independently.

## 4. Implementation Guidance

**Model Configuration:**
- **Reasoning LLM (classify + synthesis):** Gemini via `google-genai`, using the existing `GEMINI_MODELS = ("gemini-3.5-flash", "gemini-3.1-flash-lite")` fallback chain in `agent/policies.py` — primary grounds more faithfully, `-lite` is the reliably-available 503 failover. Wrapped with Instructor in `instructor.Mode.GENAI_STRUCTURED_OUTPUTS` mode (matches `decompose.py` / `generate.py`).
- **Temperature:** low / deterministic on BOTH LLM hops — routing must be reproducible (the stress-test asserts on it, D-09) and synthesis must not paraphrase-drift numbers away from source records (D-03 numeric faithfulness). Prefer `temperature=0`.
  > ⚠ planner-verify: the exact way to pass `temperature` / `max_output_tokens` through Instructor → google-genai (`config=types.GenerateContentConfig(...)` vs a `generation_config` kwarg) against the installed `google-genai`.
- **max_output_tokens:** set explicitly on both hops (never unbounded — §4b). Classify needs a tiny budget (a short tool-list JSON); synthesis is bounded to the fused-answer length.
- **Deterministic nodes call NO LLM:** the peers / forecast / redflags loaders, the scrubber, and the cite-check are pure Python — zero model calls, zero quota burn.

**Core Pattern:** bounded router → tool nodes → synthesis (wrapping `agent/graph.py`).
1. **classify** — one LLM-classify hop proposes a tool set; a deterministic allow-list clamps it (D-05). It also flags `is_advice_seeking` / `is_out_of_scope` so compliance-bait and gibberish short-circuit to a graceful refusal with no tool thrash (D-07a/c).
2. **dispatch loop** — `route` reads `tool_plan`; each tool node runs its read-only loader, appends a provenance-tagged entry to `tool_results`, **pops itself** from `tool_plan`, **increments `tool_calls`**, and returns to the router. Bounded by the counter (zero free cycles — the `_route_scrub` pattern generalized).
3. **drhp_rag** — the embedded subgraph (D-02); it fills the shared `grounded_answer` / `refusal` `GraphState` keys exactly as standalone, preserving gate1 / scrub-retry / cite-check untouched.
4. **synthesize** — fuses `tool_results` + `grounded_answer` into ONE cited answer, then **re-applies** `compliance/scrubber.py` + the deterministic cite-check — now extended so tool-derived numbers validate against the tool's SOURCE RECORD (not only DRHP spans), D-03. On any tool error/abstain OR a budget-trip, it emits the honest labelled partial from whatever grounded content exists — never fabricating the missing part (D-08).

**Tool Use:** the four capabilities are **deterministic read-only NODES, not LangChain `@tool` / `ToolNode`.**
- Rationale: storage-is-the-integration-bus (D-01) — the tools READ committed `data/*.json` via the existing loaders (`ForecastRecord.from_json`, peer/redflag loaders) and return the already-validated Pydantic records. They are NOT LLM-invoked function-calls in a ReAct loop. `ToolNode` would (a) reintroduce the ReAct tool-calling loop the bounded invariant forbids and (b) hand the LLM authority to invent tool calls. The LLM's ONLY tool authority is the single clamped classify hop.
- A tool node is a plain `SupervisorState`-in / `SupervisorState`-out function, identical in shape to `retrieve.run` / `emit.run`:
```python
# agent/tools/query_forecast.py
from agent.forecast_schema import ForecastRecord
from agent.cache.semantic_cache import cached               # D-06 semantic cache wrapper

def run(state: SupervisorState) -> SupervisorState:
    drhp_id = state["drhp_id"]                              # single-IPO scope (E3 deferred)
    try:
        rec = cached("forecast", drhp_id, _load_forecast)  # reads data/forecasts/<id>.json
        result = {"tool": "query_forecast", "record": rec.model_dump(),
                  "provenance": f"data/forecasts/{drhp_id}.json",
                  "abstain": rec.is_abstain}                # honest abstain is first-class (D-08)
    except FileNotFoundError:
        result = {"tool": "query_forecast", "record": None,
                  "provenance": None, "abstain": True}      # honest "no band" — never fabricate
    plan = [t for t in state["tool_plan"] if t != "query_forecast"]
    return {**state, "tool_plan": plan,
            "tool_calls": state.get("tool_calls", 0) + 1,
            "tool_results": state.get("tool_results", []) + [result]}
```
- **GMP** folds in read-only alongside forecast (D-04): the forecast tool also surfaces the GMP-vs-model gap as display context; GMP is NEVER a model feature (P4). `data/gmp/*.json` is read for display only.

**State Management:**
- `SupervisorState(GraphState)` — a superset `TypedDict` adding `hops: int`, `tool_calls: int`, `tool_plan: list[str]`, `tool_results: list[dict]`, `started_at: float` (wall-clock backstop), `is_partial: bool`. Shared keys keep the subgraph contract intact (pitfall #1).
- **Persistence:** `MemorySaver` in unit tests (as today); `SqliteSaver` in the app so the D-06 cache TTL spans runs. `thread_id` per session; a fresh `thread_id` per invoke isolates runs, exactly as `invoke_with_tracing` already does. The subgraph is compiled `checkpointer=None` (parent owns persistence — pitfall #2).
- **Reducers:** with a SERIAL bounded dispatcher, `{**state, ...}` overwrite (as existing nodes do) is fine.
  > ⚠ planner-verify: if the planner ever fans tools out in PARALLEL, `tool_results` MUST use an additive reducer — `Annotated[list, operator.add]` — or LangGraph raises `InvalidUpdateError` on the concurrent write. Keep serial for v1 to sidestep this.

**Context Window Strategy:**
- Bounded fan-in: at most `MAX_TOOL_CALLS` results reach synthesis, each a small structured record (a forecast band, a peer row set, a red-flag table), so the fused prompt stays well within Gemini's window even with the top-5 reranked DRHP chunks.
- The DRHP-RAG subgraph already caps context at `RERANK_TOP_K=5`; do NOT re-expand in synthesis — pass the subgraph's `grounded_answer` + `claims`, not raw chunks, into fusion.
- Single-IPO scope keeps totals small; if a fused answer ever approaches the window, drop the lowest-priority `tool_result` (peers before DRHP grounding) rather than truncating citations or the disclaimer.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs with Pydantic

Two LLM hops emit structured output — the **classify router** and the **synthesis fusion** — both via Instructor over `google-genai`, exactly like `agent/nodes/decompose.py`.

Routing-hop model (the allow-list `Literal` means the model literally cannot name a non-existent tool):
```python
# agent/nodes/classify.py
from typing import Literal
from pydantic import BaseModel, Field

ToolName = Literal["drhp_rag", "query_peers", "query_forecast", "query_redflags"]

class RoutingDecision(BaseModel):
    """Bounded LLM-classify output (D-05)."""
    tools: list[ToolName] = Field(
        default_factory=list, max_length=4,
        description="Read-only tools needed, in priority order. Empty ⇒ out-of-scope/refuse.",
    )
    is_advice_seeking: bool = Field(
        ..., description="True if asking buy/sell/subscribe/target-price judgement (D-07a).")
    is_out_of_scope: bool = Field(
        ..., description="True for off-topic/gibberish/cross-IPO (D-07c/d) ⇒ no tool thrash.")
```

Instructor integration (mirrors `decompose._call_llm`, incl. the GEMINI_MODELS failover):
```python
import instructor
from google import genai
from agent.policies import GEMINI_MODELS

def _llm_classify(question: str) -> RoutingDecision:
    client = instructor.from_genai(genai.Client(), mode=instructor.Mode.GENAI_STRUCTURED_OUTPUTS)
    messages = [
        {"role": "system", "content": _load_prompt("classify.md")},  # NEVER interpolate the user Q (T-1-01)
        {"role": "user", "content": question},
    ]
    last_exc = None
    for model in GEMINI_MODELS:                       # 503 on primary → -lite fallback
        try:
            return client.chat.completions.create(
                model=model, response_model=RoutingDecision,
                messages=messages, max_retries=2,     # Instructor re-prompts on ValidationError
            )
        except Exception as exc:                      # transport/503 → next model
            last_exc = exc
    raise last_exc
```

Synthesis reuses the LOCKED `Claim` / `GroundedAnswer` contract so the SAME cite-check runs unchanged, adding per-tool provenance for D-03:
```python
from agent.schemas import Claim

class FusedClaim(Claim):                # extends the locked schema — keep claim_id regex + span validators
    source_tool: str                    # "drhp_rag" | "query_peers" | "query_forecast" | "query_redflags"
    source_record_id: str               # the data/* record the NUMBER traces to (D-03 provenance)

class FusedAnswer(BaseModel):
    answer_prose: str                   # {{claim_id}} markers → same ui/citation_chip renderer
    claims: list[FusedClaim]
    is_partial: bool = False            # D-08 honest-partial flag
    unaddressed: list[str] = Field(default_factory=list)
```
> ⚠ planner-verify: subclassing `Claim` must NOT loosen the `^c_[a-z0-9]{6,16}$` regex or the span-offset validators — those are cross-phase invariants (`agent/schemas.py`).

**Retry logic:** Instructor `max_retries=2` re-prompts the model with the Pydantic `ValidationError` on schema violation; the `GEMINI_MODELS` loop handles transport/503 failover; a Tenacity `@retry(stop_after_attempt(3))` wrap (as in `decompose.py`) absorbs transient network errors. **Log** every validation failure + the model that served the call to Langfuse. **Surface:** if all retries + both models fail, the classify hop returns an empty/out-of-scope decision → deterministic graceful refusal, never a crash (D-07c); a synthesis failure degrades to the honest partial from `tool_results` (D-08).

### Async-First Design

LangGraph exposes sync `.invoke` / `.stream` and async `.ainvoke` / `.astream`. The existing graph is invoked **synchronously** inside `invoke_with_tracing`, and Streamlit runs sync — keep the supervisor **sync-first for v1** to match. The read-only tools are local file reads (no network) and Instructor calls are sync, so there is **no async win** here.
- **The one mistake:** calling `asyncio.run()` / `.ainvoke` from inside Streamlit's already-running loop → `RuntimeError: This event loop is already running`. Stay sync and avoid the footgun.
- **Stream vs await:** use `supervisor.stream(..., subgraphs=True)` to surface per-tool progress in the chat UI (subgraph steps are hidden without `subgraphs=True` — Pitfall #4). Use plain `.invoke` for the offline stress-test suite (D-09), asserting on the FINAL validated state. **Never** assert scrub / cite-check on streamed partials — validate the returned final state.

### Prompt Engineering Discipline

- **System vs user separation is a SECURITY control here** (T-1-01, D-07b jailbreak): the raw user question is passed ONLY as the `user`-role message and NEVER interpolated into the system prompt — exactly as `decompose.py` does. This is what makes "ignore previous instructions / reveal the system prompt / drop the disclaimer" fail.
- **Few-shot:** carry a few INLINE exemplars in the classify prompt covering the four D-07 categories (advice-bait → `tools=[]`, `is_advice_seeking=True`; gibberish → `is_out_of_scope=True`; cross-IPO → `is_out_of_scope=True`) so routing is stable; do NOT dynamically retrieve them. One inline synthesis exemplar showing a fused DRHP + peer + forecast answer with per-number provenance.
- **Token budget:** set `max_output_tokens` explicitly on both hops — never unbounded (an unbounded synthesis call is a free-tier quota AND latency risk). The banned-token scrubber + disclaimer are enforced AFTER generation regardless of the prompt — the prompt is not the compliance boundary.

### Context Window Management

This is a **bounded multi-tool agent**, so long-conversation compaction / summarization does NOT apply — context is bounded *structurally* by `MAX_TOOL_CALLS` and the top-5 rerank cap. Fusion input = `grounded_answer` + small structured tool records, never raw retrieval. If ever over budget, drop the lowest-priority `tool_result` (peers) before DRHP grounding, and NEVER truncate the disclaimer or citations. The **D-06 cross-run semantic cache doubles as context management**: a cache hit skips the tool entirely, keeping both the window and the quota lean.

### Cost and Latency Budget

- **The ceiling is Gemini free-tier RPM / RPD (requests-per-minute / -day), NOT dollars** ($0 on the free tier). Per user query the agent makes at most: 1 classify hop + (≤ `MAX_TOOL_CALLS` DRHP-RAG generate/decompose calls) + 1 synthesis hop. Budget the D-06 hop/tool bounds so the WORST-case adversarial query stays within a handful of Gemini calls — it must never fan out to dozens (P8).
- **Caching (two layers):** (1) the D-06 semantic tool-result cache with a similarity threshold catches near-duplicate calls within AND across runs (TTL spans runs → protects the demo / free-tier quota, D-12); (2) the deterministic loaders need no LLM, so they are already "free" beyond a file read. Pre-index the corpus + warm-keep the Space (P19).
- **Cheaper-model routing:** run the high-frequency classify hop on `gemini-3.1-flash-lite` (cheaper / faster) and reserve `gemini-3.5-flash` for the faithfulness-critical synthesis fusion — mirrors the existing GEMINI_MODELS posture and cuts both latency and quota burn on the most-called hop.
- **Deploy-layer backstop (D-12):** per-session / IP rate-limit + a hard daily cap aligned to the Gemini free-tier RPD, with the graceful "demo quota reached — explore the read-only surfaces / recorded walkthrough" fallback. This complements the per-run hop budget.

## 7. Production Monitoring

**Tracing Tool:** **Langfuse** — *detected existing tool* (`app/observability/langfuse_client.py`, `trace_enrichment.py`, `trace_decorators.py`; `invoke_with_tracing()` is the enriched entrypoint). **Overrides the template's Arize Phoenix default** — the project is already fully instrumented on Langfuse Cloud (free tier), with `emit_enriched_trace()` attaching cost/latency/tool-call metadata + a `failure_mode` custom score. Phase 6.3 **extends** this, it does not replace it.

**Key Metrics to Track:**
- **Hop count + tool-call count per run** — via `count_tool_calls(final_state)` (stream with `subgraphs=True` so nested DRHP-RAG tool calls are not under-counted, Pitfall #4).
- **Budget-trip rate** — fraction of runs hitting the hop / tool-call / wall-clock bound (the P8 health signal).
- **Refusal-reason taxonomy** — extend the existing `FAILURE_MODES` custom scores with new supervisor-level modes: `budget_trip`, `advice_bait_refused`, `jailbreak_blocked`, `honest_partial`, `tool_abstain` (append to the tuple; keep numeric codes stable so saved Cloud views stay filterable).
- **Latency per run** (already emitted) — p50 / p95, watched for free-tier / warm-keep drift.
- **Free-tier quota consumption** — Gemini RPD/RPM + the D-12 deploy daily-cap hits (the real ceiling is quota, not dollars — $0 on the free tier).
- **`faithfulness_deepeval`** — sampled, REPORTED, honest `-1` until calibrated (never a production gate).

**Alert Thresholds:**
- **Any `banned_token` failure_mode in production → PAGE.** The scrubber's import-time assertion should make this structurally impossible; a live occurrence means the compliance boundary is breached (the one thing that cannot ship — FM-1).
- **Any system-prompt-leak / persona-break signal → PAGE** (jailbreak succeeded — FM-1).
- **Budget-trip rate spikes above its rolling baseline → investigate** (loop/routing regression, or an adversarial-traffic shift — FM-2).
- **Latency p95 above threshold → investigate** (cold Space / quota throttling / a routing regression fanning out tools).
- **Daily-cap hits → expected, not an incident** — the graceful fallback engages; monitor only for an abnormal spike suggesting abuse.

**Smart Sampling Strategy:**
Extend the **existing failure-mode custom-score filters** in Langfuse (`emit_enriched_trace`) — weight human review toward the concerning-signal traces (the product-owner's live-transcript sampling posture, Section 1b): **advice-bait / advice-adjacent**, **very-long or empty** inputs, **retried** runs, **budget-trip** runs, **low-`faithfulness`** runs, and any **refusal / honest-partial** trace. This is the early-warning system for signal-metric divergence — when live user behaviour (e.g. rephrasing an advice question) diverges from a clean metric score, it surfaces the advice-by-implication gap the deterministic scrubber cannot see, and feeds the offline flywheel + the D-14 calibration set.
