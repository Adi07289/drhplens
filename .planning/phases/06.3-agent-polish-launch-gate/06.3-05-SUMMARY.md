## Decisions Made
- **MemorySaver, not SqliteSaver** — RESEARCH caveat (a): a fresh `thread_id` per run makes durability moot and sidesteps the HF `/tmp` ephemerality gotcha. `grep -c SqliteSaver agent/supervisor.py == 0` (acceptance criterion).
- **Thin wrapper around the compiled subgraph** — the compiled `GraphState` subgraph cannot pop itself from `tool_plan` or increment `tool_calls`, so `_drhp_rag_node` invokes it UNCHANGED then applies the tool bookkeeping. The subgraph's topology + 10 nodes are byte-for-byte unchanged (D-02, asserted).
- **The P8 bound is the explicit counter, not `recursion_limit`** — `route` trips on `hops > MAX_SUPERVISOR_HOPS`, `tool_calls >= MAX_TOOL_CALLS`, or the wall-clock backstop; `recursion_limit=50` is a pure crash backstop (caveat d).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Declared `fused_answer` + `disclaimer` channels on `SupervisorState`**
- **Found during:** Task 2 (synthesize wiring, verifying the DRHP-only e2e)
- **Issue:** LangGraph only propagates DECLARED state channels. `synthesize` returns `fused_answer` + `disclaimer`, but `SupervisorState` (Plan 01) declared neither, so both were silently dropped from the final state (the D-09 stress `_rendered` helper reads `disclaimer`; `_answer_text` reads `fused_answer`).
- **Fix:** Added the two disjoint supervisor-only channels to `SupervisorState`, and updated the Plan-01 superset contract test to permit them (its no-inherited-key-redefine / Pitfall #1 assertion is preserved — only the count of additions changed).
- **Files modified:** `agent/supervisor_state.py`, `tests/unit/test_supervisor_contracts.py`
- **Verification:** DRHP-only e2e + the D-09 envelope now see `disclaimer`/`fused_answer`; `test_supervisor_contracts.py` green.
- **Committed in:** `e6dca8c`

**2. [Rule 3 - Blocking] Wrapped the embedded subgraph in a node function (pop-self + tool_calls++)**
- **Found during:** Task 1 (routing the DRHP-only flow)
- **Issue:** `add_node("drhp_rag", compiled_subgraph)` directly would loop forever — the subgraph cannot pop `"drhp_rag"` from `tool_plan` or increment `tool_calls`, so `route` would re-dispatch it until `recursion_limit`.
- **Fix:** `_drhp_rag_node` invokes the UNCHANGED subgraph, merges its outputs, pops-self, and increments `tool_calls` (same contract as the read-only tools). Topology stays byte-for-byte unchanged (D-02). Also catches an infra failure inside the subgraph → the existing `infrastructure_error` refusal (Rule 2 robustness), never a crash.
- **Files modified:** `agent/supervisor.py`
- **Verification:** DRHP-only e2e halts deterministically (`hops==1`, `tool_calls==1`); subgraph-topology test asserts the 10 nodes unchanged.
- **Committed in:** `0e3f350`

**3. [Rule 3 - Blocking] Honest skip guard for the 4 live-drhp_rag stress cases**
- **Found during:** Task 2 (D-09 stress activation)
- **Issue:** `ci-004`, `ci-005`, `pp-003`, `pp-005` route to `drhp_rag`, which needs the live RAG stack (Qdrant + bge reranker + Gemini). The offline stress suite stubs only `classify` + `synthesize`, not the subgraph internals, so these cases would hang loading models / crash on Qdrant.
- **Fix:** Added a documented `pytest.skip` guard for exactly those 4 IDs with an honest reason (same gating as `test_agent_e2e.py` behind `--run-eval`). Not a faked pass — noted for 06.3-06 if a `drhp_rag` stub is added to the harness. The multi-tool FUSION cases `pp-001`/`002`/`004` DO run offline via the stubbed `_llm_fuse`.
- **Files modified:** `tests/eval/test_stress_suite.py`
- **Verification:** stress suite = 26 passed, 4 skipped.
- **Committed in:** `5f6ec40`
