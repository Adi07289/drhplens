# Phase 06.3 Plan 09: Public-Deploy Guards + C4 Quota Fallback Summary

**The live public chat is now free-tier-safe: a GLOBAL daily cap (`@st.cache_resource`) + a per-session throttle (`st.session_state`) bound the ~20-RPD Gemini free tier (per-IP is documented unreliable behind the HF proxy), and on exhaustion the C4 fallback degrades gracefully — the chat input is replaced by a muted card routing to the always-working read-only surfaces, while a throttle shows a non-blocking inline notice; the daily-cap value is a re-verified `policies.py` constant (NOT the stale 1500/day), a keep-warm cron pinger fights HF cold starts, and D-13 (stay Streamlit for v1) is recorded — all offline-testable, honesty-invariant, no live quota call.**

## Accomplishments

- **Deploy guard (D-12)** — `ui/deploy_guard.py` `check_and_consume(daily_cap, min_seconds) -> "ok" | "rate_limited" | "cap_exhausted"`: a GLOBAL daily cap via `@st.cache_resource` (one shared counter per Space process — app-wide, the reliable anti-DoS boundary for the free-tier RPD; midnight rollover; resets on cold start) checked FIRST, then a per-session throttle via `st.session_state` (a last-question timestamp; consumes no daily slot on a throttle), then the consume path. `is_cap_exhausted` is a read-only peek used to replace the input BEFORE the user types without mutating the counter. Per-IP is documented UNRELIABLE behind the HF proxy (`st.context.ip_address` is None) and is never the primary control (RESEARCH A4 / T-6.3-IP).
- **Re-verified cap constant (RESEARCH Pitfall 7)** — `agent/policies.py` `DEPLOY_DAILY_CAP=4` + `MIN_SECONDS_BETWEEN=4.0s`. Sized from the RE-VERIFIED current Gemini free-tier RPD (~20 RPD, project spike 002), NOT the stale CLAUDE.md 1500/day; the docstring cites the source, the `floor(RPD / worst-case flash calls per query)` sizing formula, and marks it `[ASSUMED — re-verify before deploy]`. Deliberately OFFLINE — no live RPD/quota network call (that would burn the scarce quota); the live re-verification is the human deploy step (06.3-10).
- **C4 quota/rate-limit fallback (D-12/C4)** — `ui/snapshot_chat.py` calls the guard BEFORE `invoke_supervisor`. Cap-exhausted → `_render_quota_card` REPLACES the chat input with a muted, dashed-neutral card routing to the always-working read-only (LLM-free) surfaces (snapshot/forecast/peers, `/methodology`, `/failures`) + the committed `/how_it_works` recorded-walkthrough surface — NOT a full-page interstitial. Throttled → `_render_ratelimit_notice` (a brief non-blocking notice above the still-enabled input). `ok` → proceed. `_guard_ui_action` maps the three guard states to the three mutually-exclusive UI actions. No red/green/countdown-alarm anywhere.
- **Copy + CSS** — all C4 strings centralized in `ui/copy.py` (UI-SPEC verbatim; import-time scrubber covers them; no advice-adjacent copy); additive `.drhp-quota*/.drhp-ratelimit` CSS appended to `app/static/drhplens.css` using only `--drhp-space-*` tokens, in a sentinel-delimited block asserted verdict-token-free by a grep guard.
- **Keep-warm pinger (P19)** — `.github/workflows/ping.yml` (every ~8 min cron, copied from `scripts/cron_pinger.yml`) fights the HF free-tier cold-start sleep; the `<user>` Space-URL placeholder is a documented deploy-time human step (06.3-10). The index lives on Qdrant Cloud, never `/tmp` (ephemeral).
- **D-13 recorded** — v1 stays on Streamlit + HF Spaces; Next.js is a v2 concern (resolves the Phase-5-exit re-evaluation gate) — captured in STATE.md as a constraint decision, no UI rewrite.
