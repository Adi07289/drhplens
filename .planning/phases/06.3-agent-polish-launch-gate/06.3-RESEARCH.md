## Summary

Phase 6.3 is an **extension, not a build**: every tool's data (`data/forecasts|peers|redflag|gmp/*.json`) and Pydantic contract (`agent/*_schema.py`) already exists and is committed; the 10-node DRHP-RAG graph is unchanged and stays green. The work is (1) a **hand-rolled bounded supervisor** that embeds the existing compiled graph as one node and dispatches three deterministic read-only tool nodes under a hard hop/tool-call/wall-clock counter, (2) a **synthesis node** that fuses tool outputs into one answer and re-applies the existing scrubber + an *extended* cite-check, (3) a **semantic tool-result cache** (D-06), (4) a **committed offline stress-test suite** that gates deploy (D-09), (5) the **`compliance/SEBI-REVIEW.md` self-audit** (D-10/D-11), and (6) the **HF Spaces public deploy** with in-process guards (D-12) plus the four production-stamp follow-ups (D-14).

The five AI-SPEC `planner-verify` caveats are all **resolvable now** against the installed toolchain (langgraph 1.2.2, langgraph-checkpoint 4.1.1, google-genai 2.12.1, instructor 1.15.1, streamlit 1.57.0). Two findings meaningfully shape the plan: (a) the **checkpointer choice is a near-non-issue** — because every run uses a fresh `thread_id`, `MemorySaver` is sufficient and the cross-run TTL requirement belongs to the *separate* semantic-cache module, not the checkpointer (this sidesteps the SqliteSaver-on-`/tmp` ephemerality gotcha and a version-compat risk); and (b) the AI-SPEC's `FusedClaim(Claim)` subclass **works for DRHP-grounded claims but forces fabricating DRHP-span fields for tool-derived numbers** — the honest resolution is a discriminated union (`Claim` unchanged + a sibling `ToolClaim`), which also satisfies caveat (e) by leaving the locked `Claim` contract untouched.

The launch-critical risk is regulatory, not technical: **advice-by-implication** (a clean-token answer that still leans subscribe/avoid) is the one dimension a regex cannot catch, so the deterministic stress gate covers the *envelope* (scrubber clean, disclaimer present, no leak, bounded hops) while the implication-judge stays a **separate REPORTED lane** until the D-14 human calibration clears — mirroring the existing `-1` faithfulness posture.

**Primary recommendation:** Build the supervisor with `MemorySaver` (fresh `thread_id` per run, matching the existing graph) + a dedicated in-process semantic-cache module (reusing the already-loaded bge-m3 embedder); keep `Claim` verbatim and add a sibling `ToolClaim` for tool-derived provenance; make the stress suite stub the two LLM hops so the *deterministic guardrail envelope* is asserted offline; protect the deploy with a **global daily cap + per-session throttle** (per-IP is unreliable behind the HF proxy — flag it), keep-warm via the existing `cron_pinger.yml`; and sequence the three human-in-the-loop D-14 items (`autonomous: false`) so only WR-03 is executor-completable end-to-end.

## Resolved `planner-verify` Caveats (the AI-SPEC's 5 open items)

> These are the centerpiece of this research. Each is verified against the *installed* toolchain, not training data.

### Caveat (a) — `SqliteSaver` constructor for a long-lived Streamlit singleton  → **RESOLVED**
**Finding (HIGH):** `SqliteSaver.from_conn_string(...)` **is a `@contextmanager`** (`@classmethod @contextmanager def from_conn_string(cls, conn_string) -> Iterator[SqliteSaver]`) — it closes the connection on `__exit__`, so it is **wrong for a module-level singleton**. The correct long-lived form passes a `sqlite3.Connection` with `check_same_thread=False` directly: `SqliteSaver(sqlite3.connect(path, check_same_thread=False))`. `setup()` is auto-called by cursor ops (do not call directly). `[CITED: github.com/langchain-ai/langgraph libs/checkpoint-sqlite/…/__init__.py]`

**But the sharper finding (HIGH) — you probably don't need `SqliteSaver` at all.** The checkpointer persists conversation state *per `thread_id`*. The existing app (`invoke_with_tracing`) mints a **fresh `thread_id` per invoke**, so runs are isolated and there is **no cross-run conversation memory to preserve** — `MemorySaver` already satisfies the supervisor exactly as it does the existing graph. The "TTL that spans runs" in D-06 is a property of the **separate semantic-cache module** (keyed by a semantic hash of the tool call, *not* `thread_id` — this is literally AI-SPEC Pitfall #5), not of the checkpointer. Adding `SqliteSaver` on HF Spaces would also write to **ephemeral `/tmp`** (wiped on cold start — §Environment) for zero durability benefit, and pulls a new package with a version-compat question.
- **Recommendation:** keep `MemorySaver` for the supervisor checkpointer (parity with `agent/graph.py`); compile the embedded DRHP-RAG subgraph `checkpointer=None` (parent owns persistence — AI-SPEC Pitfall #2). Put "spans runs" in the semantic-cache module. If a future phase adds real multi-turn memory, revisit `SqliteSaver(sqlite3.connect(..., check_same_thread=False))` **with a persistent-storage-backed path**, never `/tmp`.
- If the planner still wants `SqliteSaver`: `langgraph-checkpoint-sqlite==3.1.1` is the current release and a `--dry-run` resolve **installs cleanly against the pinned `langgraph-checkpoint 4.1.1`** (pulls `aiosqlite`, `sqlite-vec`). `[VERIFIED: pip dry-run 2026-08-05]`

### Caveat (b) — `temperature` / `max_output_tokens` through Instructor → google-genai  → **RESOLVED**
**Finding (HIGH):** In the installed `instructor 1.15.1`, the gemini provider (`instructor/providers/gemini/utils.py`) contains an `OPENAI_TO_GEMINI_MAP` that maps `"max_tokens" → "max_output_tokens"` and `"temperature" → "temperature"` and folds them into the genai `GenerateContentConfig`. So pass them as **top-level kwargs to `create()`**:
```python
client.chat.completions.create(
    model=model,
    response_model=RoutingDecision,
    messages=messages,
    temperature=0,            # forwarded → GenerateContentConfig.temperature
    max_tokens=256,           # forwarded → GenerateContentConfig.max_output_tokens
    max_retries=2,
)
```
`google.genai.types.GenerateContentConfig` **does expose** `temperature` and `max_output_tokens` (verified: both present, 34 config fields). Do **not** hand-build a `config=types.GenerateContentConfig(...)` — Instructor owns the `config` object (it injects `response_mime_type`/schema for structured output); a user-supplied `config=` risks clobbering that. Use the flat kwargs. `[VERIFIED: installed instructor 1.15.1 source + google-genai 2.12.1]`

### Caveat (c) — parallel-tool fan-out reducer vs serial dispatch  → **RESOLVED: serial for v1**
**Finding (HIGH):** Keep the **serial** bounded dispatcher (one tool per hop, pop-self + increment, re-enter router). With serial dispatch, the existing `{**state, ...}` overwrite pattern is correct and `tool_results` needs no special reducer. Parallel fan-out would require `tool_results: Annotated[list, operator.add]` (additive reducer) or LangGraph raises `InvalidUpdateError` on concurrent writes — extra complexity for **no latency win** here (tool nodes are local file reads; the only latency is the LLM hops, which are serial anyway). Serial also makes the **stress-suite assertions deterministic** (fixed hop order). Ship serial; document the `operator.add` reducer as the v2 upgrade path only. `[CITED: docs.langchain.com/oss/python/langgraph/graph-api]`

### Caveat (d) — `recursion_limit` is a crash backstop, not the P8 bound  → **CONFIRMED**
**Finding (HIGH):** `recursion_limit` counts *every* super-step of the whole nested run (default 1000) and raises `GraphRecursionError` — a **crash**, not the honest-partial D-08 exit, and far too loose for a free-tier quota. The **real P8 guard is the explicit `hops`/`tool_calls`/wall-clock counter routed to `synthesize`**. Set `recursion_limit` low (~2× max legal hops, e.g. if `MAX_SUPERVISOR_HOPS≈4` and `MAX_TOOL_CALLS≈4`, the legal super-step ceiling is ~1 classify + ≤4 tool + subgraph internal steps + 1 synth; set recursion_limit ≈ 40–60 as a pure backstop), **catch `GraphRecursionError` in the caller and convert to an honest partial** (never surface a crash). The wall-clock backstop is checked *inside* the router (`time.monotonic() - state["started_at"] > WALL_CLOCK_S → route synthesize`). `[CITED: docs.langchain.com/oss/python/langgraph/graph-api]`

### Caveat (e) — `FusedClaim` must not loosen the `Claim` regex / span validators  → **RESOLVED, with a schema refinement**
**Finding (HIGH):** Subclassing (`class FusedClaim(Claim): source_tool: str; source_record_id: str`) and only **adding** fields does not loosen anything — Pydantic subclasses **inherit** the `claim_id` `pattern=r"^c_[a-z0-9]{6,16}$"` and the `span_offsets` `start<=end` validators. The regex/span invariants are preserved **as long as the subclass never redefines `claim_id`, `span_offsets`, or `verbatim_span`.** So the literal caveat is satisfiable.

**But a deeper honesty problem surfaces (HIGH):** `Claim` requires **DRHP-span-shaped** fields — `source_chunk_id: str`, `drhp_page: int`, `verbatim_span: str`, `span_offsets: list[int]`, `sources: list[RetrievedChunkRef]` (`min_length=1`). A **forecast/peer/GMP-derived number has no DRHP chunk, page, or verbatim span** — forcing `FusedClaim(Claim)` onto a tool number means **fabricating** those DRHP fields, which violates the honesty invariant and the very provenance goal of D-03/C2.
- **Recommended resolution (flag for planner/discuss confirmation — refines an AI-SPEC *sketch*, contradicts no locked decision):** use a **discriminated union**, not a single subclass:
  - Keep **`Claim` verbatim** for DRHP-grounded claims → runs the **existing** cite-check unchanged (caveat (e) trivially satisfied — `Claim` is untouched).
  - Add a **sibling `ToolClaim`** (its own `BaseModel`, NOT subclassing `Claim`) for tool-derived numbers: `claim_id` (reuse the same `pattern` so the C2 chip renderer works), `text`, `value: float | str`, `source_tool: Literal["query_peers","query_forecast","query_redflags"]`, `source_record_id: str` (the `data/*.json` path/key + field the number traces to). No `drhp_page`/`verbatim_span`/`RetrievedChunkRef`.
  - `FusedAnswer.claims: list[Claim | ToolClaim]` (Pydantic tagged/duck union). The **extended cite-check dispatches on type**: `Claim` → existing DRHP span + `CITE_CHECK_TOKEN_RATIO` fuzzy check; `ToolClaim` → resolve `source_record_id` in the committed record and **reconcile the number** with the existing `NUMERIC_GROUNDING_REL_TOLERANCE` (0.01) + lakh/crore unit normalization (already implemented for the Phase-3 numeric-faithfulness path — reuse it).
- This maps cleanly onto UI-SPEC C2 (numbered superscripts for `Claim`/DRHP via the existing `render_citation_expanders`; lettered `ꜰ`/`ᴾ`/`ᴳ` superscripts for `ToolClaim`) and onto FM-3 (an unresolvable number **fails cite-check and is dropped**, never rendered). `[VERIFIED: agent/schemas.py + agent/policies.py source]`

### Pattern 2: Deterministic router with wall-clock backstop (the P8 guard)

import time
from agent.policies import MAX_SUPERVISOR_HOPS, MAX_TOOL_CALLS, WALL_CLOCK_S

### Pattern 3: In-process semantic tool-result cache (D-06)
**What:** a small module reusing the already-loaded bge-m3 embedder; keyed by `(drhp_id, normalized_question)`; cosine-similarity lookup scoped to the same `drhp_id`; TTL by wall-clock.
```python
# agent/cache/semantic_cache.py  (sketch — ~40 lines, no new dependency)
import time, threading
from dataclasses import dataclass, field
from agent.policies import DEDUP_THRESHOLD, CACHE_TTL_S

@dataclass
class _Entry: vec: list[float]; value: dict; ts: float
_STORE: dict[str, list[_Entry]] = {}     # keyed by drhp_id → entries (never cross-IPO)
_LOCK = threading.Lock()

def cached_answer(drhp_id: str, question: str, embed, compute):
    """embed(str)->vec (reuse the bge-m3 st.cache_resource); compute()->dict (the LLM run)."""
    now = time.monotonic(); qv = embed(question)
    with _LOCK:
        live = [e for e in _STORE.get(drhp_id, []) if now - e.ts < CACHE_TTL_S]  # TTL sweep
        _STORE[drhp_id] = live
        for e in live:
            if _cos(qv, e.vec) >= DEDUP_THRESHOLD:
                return e.value                                     # quota-saving hit
    value = compute()
    with _LOCK:
        _STORE.setdefault(drhp_id, []).append(_Entry(qv, value, now))
    return value
```
- **Scoping / no-leak (answers the orchestrator's Q2):** every entry lives under its `drhp_id` bucket → **no cross-IPO leakage** by construction. It is **independent of `thread_id`**, so it composes with the checkpointer without interfering (checkpointer isolates conversation state per fresh `thread_id`; the cache persists across those runs — exactly AI-SPEC Pitfall #5). Cross-*session* sharing of a grounded answer is **safe and desired** (answers are deterministic-grounded, not personalized — no PII, no per-user state).
- **Two cache layers, be explicit:** (1) the **deterministic tool loaders** (peers/forecast/redflags/GMP) depend only on `(tool, drhp_id)`, not on question text → cache them by an **exact key** (or just rely on the cheap file read); **no embedding needed** for those. (2) the **quota-scarce LLM hops** (classify + DRHP-RAG + synthesis) depend on free-text → **this** is where semantic similarity earns its keep. Say so in the plan so the executor doesn't over-engineer embeddings onto the static loaders.
- **Defaults (calibration, planner discretion):** `DEDUP_THRESHOLD ≈ 0.95` cosine (high, to avoid serving a subtly-different question), `CACHE_TTL_S ≈ 6–24h` (demo-window; committed data is static so staleness risk is low). Tune like the other `policies.py` constants.
- **Persistence:** in-process dict is best-effort — **lost on HF cold start** (`/tmp` ephemeral). That is acceptable: the cache is a quota-optimizer, not a source of truth. Do NOT back it with a `/tmp` sqlite expecting durability.

### Pattern 4: Deploy-layer guards (D-12) — global daily cap + per-session throttle

The **global cap is what actually protects the Gemini RPD** — it is app-wide, not per-user. Frame D-12's "per-session/IP" as "per-session (+ best-effort IP if available)". `[VERIFIED: streamlit docs + community — st.context.ip_address None behind proxy]`

### Anti-Patterns to Avoid
- **Using `recursion_limit` as the P8 bound** — it crashes, doesn't honest-partial (caveat d).
- **`SqliteSaver` on `/tmp` for "durability"** — wiped on cold start; adds a package for nothing (caveat a).
- **Embedding the static tool loaders into the semantic cache** — their result is a pure function of `(tool, drhp_id)`; use an exact key, not similarity.
- **Per-IP rate limiting on HF Spaces** — unreliable behind the proxy; use session + global cap.
- **Forcing tool numbers through `Claim`** — fabricates DRHP spans; use `ToolClaim` (caveat e).
- **Interpolating the raw user question into the system prompt** — the jailbreak defense (T-1-01) is that the question is ONLY a `user`-role message. Keep it that way in classify + synthesis.
- **Asserting scrub/cite-check on streamed partials** — validate the returned final state (stream is for UI progress only).
- **Hard-gating the DeepEval judge** — non-deterministic; a flaky gate (T-6.1-16). Keep REPORTED.

## Common Pitfalls

### Pitfall 1: State-key collision between supervisor and subgraph
**What goes wrong:** `SupervisorState` reuses a `GraphState` key with a different meaning → the embedded DRHP-RAG subgraph silently clobbers supervisor state (or vice-versa).
**How to avoid:** `SupervisorState(GraphState)` is a **superset** — shared keys keep ONE meaning; supervisor-only keys (`hops`, `tool_calls`, `tool_plan`, `tool_results`, `started_at`, `is_partial`) are disjoint. Never redefine an inherited key.
**Warning sign:** the subgraph's `grounded_answer`/`refusal` mysteriously reset after a supervisor hop.

### Pitfall 2: Checkpointer double-compile / non-propagation
**What goes wrong:** the embedded subgraph carries its own checkpointer → double persistence / `thread_id` confusion.
**How to avoid:** compile the subgraph `build_graph(checkpointer=None)`; only the supervisor carries the checkpointer (parent propagates). The `build_graph(checkpointer=None)` signature already supports this.

### Pitfall 3: `thread_id` mandatory once a checkpointer is attached
**What goes wrong:** invoking without `config={"configurable":{"thread_id":...}}` crashes — this **silently zeroed the numeric-faithfulness eval** once.
**How to avoid:** fresh `thread_id` per invoke (as `invoke_with_tracing` does). Key the **semantic cache by `(drhp_id, question)`, NOT `thread_id`.**

### Pitfall 4: Subgraph tool-calls under-counted in traces
**What goes wrong:** `supervisor.stream(...)` hides steps *inside* the DRHP-RAG subgraph → `count_tool_calls` under-reports.
**How to avoid:** stream with `subgraphs=True` when the UI/Langfuse needs per-tool events; filter by namespace. Use plain `.invoke` for the stress suite (assert on final state).

### Pitfall 5: HF Spaces `/tmp` is ephemeral + Space sleeps
**What goes wrong:** anything written to `/tmp` (a `SqliteSaver` file, a persisted cache, a re-built index) is **wiped on restart/rebuild**; the free Space **sleeps on inactivity** (30–90s cold start).
**How to avoid:** commit `data/*.json` into the repo/image; use **Qdrant Cloud (free 1GB)** for the vector index (not a local `/tmp` Qdrant); treat the semantic cache as best-effort; keep-warm via the existing cron pinger. `[VERIFIED: HF docs + community]`

### Pitfall 6: Advice-by-implication slips a clean-token lean past the scrubber
**What goes wrong:** the answer emits no banned word but frames "discount to peers + strong GMP + improving margins" so the subscribe conclusion is unmistakable — the launch-critical FM-1 breach a regex cannot catch.
**How to avoid:** the gated deterministic suite covers the *envelope*; the **implication is a separate REPORTED LLM-judge lane** calibrated by the SEBI-literate reviewer (D-14 HITL). Tighten the synthesis prompt to *describe context, never conclude*; keep GMP as the caveated gap only (D-04). Do not claim the gate catches implication — it catches tokens.

### Pitfall 7: Gemini free-tier RPD is far tighter than the old 1500/day
**What goes wrong:** planning a daily cap from stale "1500 req/day" data; spike 002 measured `gemini-3.5-flash` at ~20 RPD.
**How to avoid:** re-verify current RPD at plan time; run classify on `-lite`; make the semantic cache real; set the daily cap conservatively; the C4 fallback is the expected steady-state, not an incident.

from pydantic import BaseModel, Field
import instructor

from agent.policies import GEMINI_MODELS

## Security Domain

> `security_enforcement: true`, `security_asvs_level: 1`. This is a public, unauthenticated informational app; the threat surface is **prompt-level abuse + free-tier resource exhaustion + XSS on scraped strings**, not user data.

### Applicable ASVS Categories
| ASVS Category | Applies | Standard control |
|---------------|---------|-----------------|
| V2 Authentication | no | No accounts; public read-only demo. |
| V3 Session Management | partial | `st.session_state` for throttle only; no auth session; fresh `thread_id` per run isolates state. |
| V4 Access Control | partial | Single-IPO `drhp_id` gated through the `is_known_drhp_id` allow-list before any path (existing path-safety controls T-04/05-PATH). |
| V5 Input Validation | **yes** | Pydantic everywhere (`RoutingDecision` `Literal` tools, schema validators); raw question only a `user`-role message (T-1-01); scrubber on output; oversized/empty input handled as D-07c. |
| V6 Cryptography | no | No secrets stored by the app; keys are HF Spaces env Secrets, never committed. |
| V11 Business-logic / rate | **yes** | Deterministic P8 bound (D-06) + deploy-layer daily cap + per-session throttle (D-12) — anti-abuse + anti-exhaustion. |
| V12/V5 Output encoding | **yes** | Scraped strings (peer/GMP `source`, company names) HTML-escaped before render (existing `html.escape` posture); `unsafe_allow_html` only on sanitizer-safe app-authored HTML. |

### Known Threat Patterns for {LangGraph agent + Streamlit public deploy}
| Pattern | STRIDE | Standard mitigation |
|---------|--------|---------------------|
| Prompt injection / jailbreak ("ignore instructions / reveal system prompt / drop disclaimer") | Tampering / Info-disclosure | System/user role separation (raw Q never in system prompt, T-1-01); scrubber + disclaimer enforced post-generation; D-09 stress (b) asserts no leak. |
| Advice-by-implication (clean-token lean) | Repudiation (regulatory) | Prompt discipline (describe, never conclude) + REPORTED implication judge (D-14 calibrated); the launch-critical FM-1. |
| Unbounded tool loop / quota exhaustion (DoS on free tier) | Denial of Service | Hard hop/tool/wall-clock counter (D-06) + global daily cap + session throttle (D-12) + semantic cache. |
| Fabricated fusion (number not tracing to source) | Tampering (integrity) | Extended cite-check drops unresolved `ToolClaim`s (FM-3); numeric reconcile with existing tolerance. |
| Path traversal via `drhp_id` | Tampering | Existing `is_known_drhp_id` allow-list before any `data/*` path (T-0x-PATH controls). |
| XSS via scraped peer/GMP/company strings | Tampering (client) | `html.escape` on all untrusted strings; inline SVG only; no script in `unsafe_allow_html`. |
| Secret leakage | Info-disclosure | HF Spaces Secrets → env vars; `.env` never committed; no key in logs/traces. |
| GraphRecursionError surfaced as a crash | DoS / poor UX | Caught in the caller → honest partial (D-08); recursion_limit is a backstop only. |
