# Phase 6.1: Eval Harness + Inline Metrics + Langfuse Ops — Specification

**Created:** 2026-07-28
**Ambiguity score:** 0.115 (gate: ≤ 0.20)
**Requirements:** 4 locked
**Alias:** 6a (branch `phase6/6a-eval-harness`; brainstorm design doc `docs/superpowers/specs/2026-07-28-6a-eval-harness-design.md`)

## Goal

Promote RAG evaluation from a "measure-only Phase 1 baseline" into a first-class committed suite: a DeepEval LLM-judge faithfulness metric (reported) plus deterministic recall@k and citation-accuracy (release-gated), whose numbers are committed to `eval/reports/eval_summary.json`, surfaced as an honest system-level figure on every IPO page, and whose agent traces are enriched in Langfuse with cost/latency/tool-call counts and a failure-mode taxonomy as custom scores.

## Background

Current state, from the codebase:

- `scripts/run_eval.py` already implements deterministic `_citation_accuracy`, `_recall_at_k` (k=5 only), optional `_ragas_faithfulness` (skippable), and `_answer_coverage` — but it is framed as "Phase 1 baseline, measure-only," runs against a single 13-entry Swiggy gold set (`tests/eval/gold_set.jsonl`), and only `compute_numeric_faithfulness` is importable. The metric functions are private to the script.
- `scripts/release_gate.py` imports `compute_numeric_faithfulness` and hard-gates `numeric_faithfulness ≥ 0.95` (the sole eval release gate today, PASSES 0.957).
- `app/observability/` has live Langfuse plumbing: `langfuse_client.py` (no-op fallback when keys unset), `trace_decorators.py` (`build_callbacks_for_run` + a refusal-only failure-mode taxonomy: `low_retrieval_score / unsupported_claim / banned_token / infrastructure_error`), `cite_check_metric.py`. `agent/graph.py:invoke_with_tracing` attaches callbacks. **No cost/latency/tool-call attributes and no custom scores exist yet; there is no ops dashboard.**
- `pages/01_methodology.py` renders an eval-metrics table with **placeholder rows** (e.g. "Context recall@k · reported · Phase 6") and already reads `model_card/card_data.json` at render. IPO snapshot pages surface no eval figures.
- **DeepEval is not in the repo.** RAGAS is a referenced-but-optional dependency. `langfuse` is a declared dependency.

The gap: the metrics are private, single-corpus, and measure-only; nothing is surfaced in the UI; Langfuse traces are not enriched and carry no scores. This phase closes that gap for EVAL-01/02/05.

## Requirements

1. **Committed RAG eval suite (EVAL-01)**: An importable metric package computes faithfulness + recall@k + citation-accuracy and commits the results.
   - Current: metric functions are private to `scripts/run_eval.py`; recall is k=5 only; faithfulness is optional RAGAS; results labelled "measure-only"; no machine artifact. DeepEval absent.
   - Target: `eval/metrics/` exposes importable deterministic `recall_at_k` (reported at k=5/10/30) and `citation_accuracy` (span-overlap), plus a DeepEval `FaithfulnessMetric` wrapper (LLM-judge via Gemini). A runner emits both `eval/reports/<date>-rag-eval.md` (human) and `eval/reports/eval_summary.json` (machine). RAGAS retained only as a flag-gated offline cross-check, out of CI.
   - Acceptance: running the eval runner produces `eval_summary.json` with `faithfulness_deepeval`, `citation_accuracy`, `recall_at_5/10/30` populated and a matching `.md` report; `eval/metrics` functions are importable and covered by unit tests.

2. **Honest inline eval surface (EVAL-02)**: IPO pages show a system-level eval figure read from the committed artifact.
   - Current: `/methodology` shows placeholder "Phase 6" rows; IPO snapshot pages show no eval figures.
   - Target: a render component reads `eval/reports/eval_summary.json` and shows, on every IPO page, an honest system-level figure — "Measured across our N-question eval set (Swiggy DRHP, <date>, judge=<model>): faithfulness 0.xx · recall@10 0.xx · citation 0.xx" — with a link to the committed report; a per-IPO line appears **only** for IPOs that have a real gold set; the `/methodology` placeholder rows are filled with the live numbers. Plain mono figures — no red/green, no badges, no verdict UX.
   - Acceptance: an IPO page renders the system-level figure with a provenance string (n, IPO, date, judge model) and a report link; an IPO without a gold set shows **no** per-IPO number; no red/green/badge/severity classes are emitted on the eval figures; the `/methodology` rows show live values, not "reported · Phase 6".

3. **Deterministic release gates (gate posture)**: The release gate hard-blocks on the reproducible metrics; the LLM-judge is reported, not gated.
   - Current: `release_gate.py` enforces only `numeric_faithfulness ≥ 0.95`.
   - Target: `release_gate.py` additionally hard-gates `citation_accuracy ≥ 0.95` and `recall@10 ≥ 0.85` (importing the `eval/metrics` implementation so report and gate never diverge). DeepEval faithfulness is reported with a ≥0.95 target line but does **not** block. `recall@10 ≥ 0.85` is a default ratified against the spike-measured baseline. The existing numeric gate is unchanged.
   - Acceptance: with a stubbed metric below threshold, `release_gate.py` exits non-zero when `citation_accuracy < 0.95` OR `recall@10 < 0.85`; a `faithfulness_deepeval` below 0.95 does **not** cause a non-zero exit; the numeric-faithfulness gate still fires.

4. **Langfuse trace enrichment + failure-mode scores (EVAL-05)**: Every trace carries operational metrics and a failure-mode score, reviewable on Langfuse Cloud.
   - Current: callbacks attach and a refusal-only taxonomy exists; no cost/latency/tool-call attributes; no custom scores; no ops dashboard.
   - Target: each trace carries cost, latency, and tool-call count; the failure-mode taxonomy is promoted to Langfuse **custom scores** and extended beyond refusals to `retrieval_miss / cite_check_fail / judge_flag / crash`; saved Langfuse Cloud views are defined for cost/latency/tool-calls/failure-mode; representative screenshots are committed for the README/failure gallery (consumed in 6.2). The no-op fallback (keys unset) is preserved.
   - Acceptance: with Langfuse keys set, one agent run yields a trace exposing cost/latency/tool-call-count metadata and a failure-mode custom score; with keys unset the agent runs unchanged (no-op), pinned by an extended integration test.

## Boundaries

**In scope:**
- `eval/metrics/` importable package: deterministic `recall_at_k` (k=5/10/30), `citation_accuracy`, DeepEval `FaithfulnessMetric` wrapper; RAGAS flag-gated offline cross-check.
- Eval runner emitting `eval/reports/<date>-rag-eval.md` + `eval/reports/eval_summary.json` (pinned schema).
- `release_gate.py` deterministic hard gates (citation-accuracy ≥0.95, recall@10 ≥0.85) sharing the `eval/metrics` implementation.
- Inline eval-figure component on IPO pages + filling the `/methodology` placeholder rows.
- Langfuse trace enrichment (cost/latency/tool-call counts) + failure-mode custom scores + saved views + committed screenshots.
- DeepEval `assert_test` pytest lane (opt-in, needs `GEMINI_API_KEY`, non-blocking).
- The phase-start spike (DeepEval CI shape + Langfuse custom-score callbacks + measured recall@10 baseline).

**Out of scope:**
- EVAL-04 "Show your work" pane — Phase 6.2 (largely delivered already by METHOD-01 in Phase 3).
- OPS-03 committed HTML eval dashboards — Phase 6.2 (this phase enriches traces; the static HTML dashboard is 6.2).
- LAND-01 recruiter `/methodology` landing page — Phase 6.2 (6.1 only fills the existing eval-table placeholder rows).
- FAILGAL-01 browseable `/failures` gallery — Phase 6.2 (6.1 commits the Langfuse screenshots it will consume).
- Multi-tool agent orchestration + SEBI legal-review gate + public launch — Phase 6.3.
- Authoring per-IPO gold sets for non-Swiggy IPOs — future work; 6.1 shows a per-IPO number only where a gold set already exists.
- A bespoke in-app ops dashboard — Langfuse Cloud hosts the dashboard ("reviewable by the developer").
- Live per-answer faithfulness at query time — rejected (per-query LLM-judge cost/latency + demo fragility; overlaps EVAL-04).

## Constraints

- **No live LLM-judge calls at page render.** Inline figures read the committed `eval/reports/eval_summary.json` (the `card_data.json` pattern) — zero per-view cost/latency, demo-safe (P19).
- **Honesty invariant (SEBI/compliance):** eval figures use plain IBM-Plex-Mono numbers — no red/green, no badges, no severity icons, no verdict UX; every figure carries provenance (n, IPO, date, judge model) + a report link; never a per-IPO number for an IPO without a real gold set.
- **One metric implementation.** The report and the release gate both import `eval/metrics` — no re-implementation (mirrors the existing `compute_numeric_faithfulness` pattern).
- **Deterministic metrics hard-gate; the LLM-judge is reported-only** — DeepEval faithfulness is non-deterministic run-to-run and must not flake CI.
- **Langfuse must no-op cleanly** when `LANGFUSE_PUBLIC_KEY`/`SECRET_KEY` are unset (local dev, CI without secrets).
- **Free-tier only:** Gemini as the judge LLM; Langfuse Cloud free tier.
- **`recall@10 ≥ 0.85` is a default** ratified against the spike-measured baseline — set just below real performance, never above (self-block) nor trivially low (meaningless).
