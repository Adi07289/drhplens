## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| dependency resolve → build | pip resolves langfuse/deepeval/ragas; a floating major could pull the langfuse v4 OTEL rewrite | pinned version ranges |
| eval runner (trusted) → eval_summary.json → UI + release gate | the committed artifact is the single contract; a malformed/under-validated figure could surface without provenance or diverge from the gate | EvalSummary JSON (aggregate metrics, provenance) |
| eval harness → Gemini judge API | GEMINI_API_KEY leaves the process to the DeepEval GeminiModel judge | API key (env-only), top-5 reranked context |
| agent process → Langfuse Cloud | trace metadata + scores cross to a third-party SaaS | 80-char question preview, cost/latency/tool-call, failure-mode score |
| keys unset (local/CI) → agent | no-op fallback is a hard contract: absence of secrets must not change agent behavior | none (short-circuit before any client call) |
| committed eval_summary.json → rendered IPO page | untrusted-at-render JSON crosses into user-visible HTML | escaped metric strings, provenance |
| eval figure → retail user | honesty invariant governs what a number may claim (no verdict UX, no per-IPO number without a real gold set) | plain-mono figures + provenance |

Touches the integrity underlying T-6.1-13/15/17, whose declared mitigations (single impl, enforced constants) ARE present. |

T-6.1-17's declared mitigation (`sys.exit(1)` on breach) is present and tested; automating the lane is an OPS-02 deploy-phase item, not a registered-mitigation gap. |
| Faithfulness uncalibrated / judge spot-check pending | 06.1-EVAL-REVIEW.md | The ≥50-example ≥0.7 judge-vs-human calibration is not done (free-tier 20-req/day). This is WHY the honesty mitigations hold: `faithfulness_deepeval == -1` ("not measured") is withheld from surfacing (T-6.1-02/11/21/22 verified). Surfacing a real (non `-1`) faithfulness number remains gated behind that calibration. |
