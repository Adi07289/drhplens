## Accomplishments
- `ui/eval_inline.py::render_eval_inline(drhp_id)` reads the committed `eval/reports/eval_summary.json` once (`.is_file()` + try/except), renders the system-level figure with full provenance (n, ipo, generated date, judge model) + a `view report` link, and a per-IPO sub-line ONLY when `per_ipo[drhp_id]` exists.
- Faithfulness `-1.0` (the documented "not measured" sentinel) renders verbatim as `not measured` — never `0.00`/`-1.00`; a missing metric renders the em dash; a missing `report` omits the link; an absent/unreadable JSON renders a single muted fallback line without crashing.

## Decisions Made
- **Isolation test shape.** The bare substring `deepeval` collides with the required honest provenance key `faithfulness_deepeval`. The isolation test therefore enforces read-only isolation via an AST import allowlist (`json`/`pathlib`/`html`/`streamlit`/`__future__` only) — which directly forbids importing the DeepEval library — plus precise `import deepeval` / `from deepeval` forbidden tokens and a `.invoke(` / client-name scan. This satisfies "imports no LLM/agent/deepeval module" without a false positive on the JSON key.
- **Per-IPO `n`.** The pinned `Aggregate` schema (and the committed JSON) carry no `n` inside `per_ipo` entries, so the per-IPO line omits the `(n=…)` clause when absent rather than fabricate it — the UI-SPEC copy assumed a field the schema does not define.
- **`_mc_num` hoist.** Moved the shared em-dash formatter above the Evaluation block and removed the duplicate definition, so the eval rows and the model-card section share one honest formatter.
