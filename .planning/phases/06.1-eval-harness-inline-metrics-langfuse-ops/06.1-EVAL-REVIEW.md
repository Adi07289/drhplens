## Critical Gaps (must fix before production)

1. **[CRITICAL] Faithfulness dimension is unmeasured and the judge is uncalibrated.** The DeepEval wrapper exists and honestly reports `-1`, but there is no committed faithfulness number and the **≥50-example / ≥0.7 judge-vs-human calibration is not done**. Until calibration passes, the system's central RAG-quality dimension (groundedness) has no measured signal. *Honest, but incomplete — this is the gate to actually trusting the judge.*
2. **[CRITICAL] The P10 ≥50-example human spot-check was not performed, yet deterministic figures are surfaced inline.** AI-SPEC §5/§7 call this the "non-negotiable calibration step before any figure is surfaced." recall/citation figures render on every IPO page without it. (Both are saturated at 1.00 on coarse spans, so the risk of surfacing a hollow "win" is live.)
3. **[CRITICAL] No automated CI gate lane.** The release gate is a manual `make release` only; no GitHub Actions workflow blocks a PR/push on citation/recall/numeric regressions. Enforcement currently depends on developer discipline — the exact failure mode the gate was built to prevent ("enforcement over discipline").
4. **[CRITICAL] Production queries are not traced.** `ui/snapshot_chat.py` bypasses `invoke_with_tracing`, so the Langfuse enrichment, failure-mode taxonomy distribution, and smart-sampling described in AI-SPEC §6/§7 have **no production data** — production monitoring is effectively unwired despite the phase title "…+ Langfuse Ops."

## Remediation Plan

### Must fix before production
1. **Wire the production path to tracing.** Change `ui/snapshot_chat.py:179` `graph.invoke({...})` → `invoke_with_tracing(state, question)` so every real user query emits an enriched trace + failure-mode score. Add a test asserting the production Q&A handler calls the traced entrypoint (guards against silent regression to `graph.invoke`).
2. **Add the automated CI gate lane.** Create `.github/workflows/eval-gate.yml` that on PR/push runs `python scripts/run_eval.py` then `python scripts/release_gate.py` (deterministic lane, `$0`, no Gemini) and fails the build on non-zero exit — plus `ruff` + the offline eval pytest (`tests/eval/`, `tests/unit/test_eval_*`). Keep the DeepEval `assert_test` lane opt-in / non-blocking (key-gated), exactly as AI-SPEC §5 specifies.
3. **Run the ≥50-example human spot-check and judge calibration.** Review answer-vs-cited-span-vs-retrieved-context for ≥50 gold examples; compute judge-vs-human correlation; only surface a faithfulness figure once ≥0.7 is reached. Record the calibration result as a committed artifact. Until then keep faithfulness at `-1` (as now).
4. **Have `make release` regenerate before it gates.** Make the `release` target run `run_eval.py` before `release_gate.py` (or have the gate assert the artifact's `generated` date is current) so a stale committed `eval_summary.json` cannot pass the deterministic gate.

### Should fix soon
5. **Tighten gold `expected_sources` to ≤2–3-page answer spans** (spike 003 / measured decision #7), then re-measure and re-ratify the recall@10 floor — this is what turns recall *and* citation from saturated floors into discriminating signals.
6. **Add the missing gold-set archetypes:** labelled RPT-attribution questions (question → correct party → expected span) and numeric unit/period edge cases (crore↔lakh, current-vs-prior FY) — both are Critical domain failure modes currently untested.
7. **Fix the citation interpretation asymmetry.** Add the same "saturated on coarse spans" caveat to the citation paragraph that the recall paragraph carries, until spans are tightened — so citation is not framed as "the real signal" while it is in fact equally saturated at 1.00.
8. **Implement the read-time schema guardrail as specified.** Have `render_eval_inline` validate the JSON against `EvalSummary` (fail-closed → empty-state) instead of defensive `.get()` fallbacks, so a malformed/empty-judge artifact is suppressed rather than partially rendered.

### Nice to have
9. Centralize the calibration + gold-set-tightening deferrals in `deferred-items.md` (currently only the two test flakes live there; the substantive follow-ups are scattered across the report/summaries/spike).
10. Reconcile the inline provenance copy ("Measured across our 13-question eval set") with the fact that 11/13 grounded questions are scored for the deterministic metrics (2 refusal-eligible excluded) — minor, but the report is precise about 11/13 while the inline rounds to "13."
11. Broaden the `faithfulness_deepeval` opt-in test's 429 skip-guard so a differently-worded rate-limit error can't red the default suite (deferred-items #2).
