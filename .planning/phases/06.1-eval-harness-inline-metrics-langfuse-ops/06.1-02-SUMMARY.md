## Issues Encountered
- **Local `.env` repopulates `GEMINI_API_KEY` under pytest.** `env -u GEMINI_API_KEY` did not stop the opt-in lane from running live: DeepEval's auto-registered pytest plugin calls `load_dotenv()`, which walks up from its own `.venv/…/site-packages` path (the `.venv` lives inside the repo) and finds the repo's `.env`. This is a LOCAL-DEV convenience, not a CI condition — real CI has no `.env`, so the key stays unset and the lane skips. Proven both directions:
  - key genuinely absent (`GEMINI_API_KEY=""`, which `load_dotenv(override=False)` will not overwrite): `1 passed, 1 skipped in 0.05s` (sentinel passes, opt-in lane SKIPPED, no judge call) — the default-CI-safe path.
  - key present (local `.env`): the live `gemini-3.5-flash` judge measures spike 002's faithful fixture and the `assert_test` lane passes (~8s) — the end-of-phase human-check path.
