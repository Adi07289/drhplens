<objective>
Make Langfuse tracing actually work and enrich it (EVAL-05). The spike (001) found `get_callback_handler()` has been silently returning `_NoOpCallbackHandler` because the LangChain CallbackHandler needs the full `langchain` package (absent on both v2 and v4) — so "every agent run writes a trace" has NOT held. This plan instruments via the DIRECT client API instead (measured decision #5), so every run emits a real trace with cost/latency/tool-call-count metadata + a failure-mode custom score.

Delivers (measured decision #5; spike 001; SPEC requirement 4; design doc §4.4):
- `app/observability/trace_enrichment.py` — `emit_enriched_trace(...)` using `lf.trace(name, metadata=..., tags=...)` → `trace.score(name="failure_mode", value, comment)` → `lf.flush()`, plus a `FAILURE_MODES` taxonomy extending the 4 refusal reasons (`low_retrieval_score / unsupported_claim / banned_token / infrastructure_error`) with `retrieval_miss / cite_check_fail / judge_flag / crash`.
- `agent/graph.py::invoke_with_tracing` — wrapped to measure latency, count tool/node calls, derive the failure mode from `final_state`, and emit the enriched trace; no-op preserved when keys unset; `flush()` invoked.
- `tests/integration/test_langfuse_trace.py` — extended: custom-score attach (opt-in) + a hardened no-op-fallback pin.

Purpose: EVAL-05 — every trace reviewable on Langfuse Cloud with cost/latency/tool-call counts + failure-mode taxonomy (SPEC requirement 4). This is "make tracing work, then enrich" (spike 001 planner-critical flag), not merely enrich.
Output: the direct-API enrichment module + graph wiring + tests; the no-op fallback stays intact.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent process → Langfuse Cloud | trace metadata + scores + keys cross to a third-party SaaS; a leak or a crash-on-trace would breach observability isolation |
| keys unset (local/CI) → agent | the no-op fallback is a hard contract: absence of secrets must never change agent behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-6.1-07 | Denial of Service | tracing crashes the agent | mitigate | All Langfuse calls are try/except-swallowed (mirror cite_check_metric); a trace failure never breaks the response path |
| T-6.1-08 | Information Disclosure | LANGFUSE_SECRET_KEY / question text | mitigate | Keys read only via langfuse_client from env; only an 80-char question_preview is sent; no full DRHP text in metadata |
| T-6.1-09 | Tampering | silently-no-op tracing (the spike finding) | mitigate | Route via the direct client API (verified live in spike 001), not the langchain-dependent CallbackHandler; a no-op pin test guards the disabled path |
| T-6.1-10 | Repudiation | dropped scores on process exit | mitigate | flush() called in invoke_with_tracing + the runner/CI path (mandatory for short-lived processes) |
</threat_model>
