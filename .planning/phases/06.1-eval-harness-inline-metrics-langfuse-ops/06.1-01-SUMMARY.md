# Phase 6.1 Plan 01: Eval Metrics Package + Dependency Pins Summary

**Stood up `eval/metrics/` — the single importable deterministic-metric package (span-overlap `recall_at_k` over the 50 retrieved candidates + `citation_accuracy`) plus the pinned `EvalSummary` UI contract that enforces the honesty invariant — so the committed eval report and the release gate can never diverge.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3/3
- **Files created:** 6
- **Files modified:** 2
- **Tests:** 28 passing (10 metrics + 18 schema)

## Accomplishments
- `recall_at_k` and `citation_accuracy` are importable, pure, model-free span-overlap functions lifted from `scripts/run_eval.py` — the ONE implementation both the 06.1-04 runner and the 06.1-05 release gate will import (mirrors `compute_numeric_faithfulness`).
- `recall_at_k` demonstrably slices over the full candidate list: k=5 → 0.0, k=10 → 1.0, k=30 → 1.0 when the matching chunk sits at index 7 (proves it operates over `retrieved_chunks`, not the 5-capped reranked window).
- `EvalSummary` / `Aggregate` / `Corpus` Pydantic models pin the `eval_summary.json` UI contract per AI-SPEC §4b — rejecting an empty `judge_model`, out-of-range metrics, and `n_questions <= 0`, while accepting the `-1.0` faithfulness "not measured" sentinel.
- Phase deps pinned in both `requirements.txt` and `pyproject.toml` (`langfuse<3`, `deepeval>=4.1,<5`, `ragas>=0.4,<0.5` offline-only) with **no `langchain` dependency introduced**.
