# Phase 6.1 — UI Design Contract

> Visual and interaction contract for the **EVAL-02 honest inline eval-metric surface**.
> Design system is LOCKED (DRHPLens "Graphite + Amber" Deep-Slate dark theme). This spec
> codifies already-made decisions — it opens no new design questions.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** two render surfaces only —
1. **Surface 1** — the inline eval-figure component on every IPO snapshot page (`pages/02_snapshot.py`).
2. **Surface 2** — filling the existing eval-metrics placeholder rows on `pages/01_methodology.py`.

Both read the committed `eval/reports/eval_summary.json` at render (the `card_data.json` pattern) —
**zero live LLM-judge calls at page load** (P19, constraint). All eval/agent metric _computation_
(EVAL-01, EVAL-05 Langfuse enrichment) is out of this UI contract's scope; it belongs to the AI-SPEC.

**Governing constraint — HONESTY INVARIANT (SEBI/compliance, non-negotiable):** NO red/green, NO
badges, NO severity icons, NO verdict UX, NO color-coded pass/fail on any eval figure. Eval numbers
are PLAIN IBM-Plex-Mono figures. Eye-catch comes from **structure/typography/orientation only**.
Accent amber is reserved for the report **link** — never to signal "good/bad". A high score and a
low score MUST render in byte-identical styling.

never an inline `<style>` from a module). CSS is injected every run via `load_global_css` (it vanishes
after `st.rerun()`).

## Color

60/30/10 split — reuse LOCKED `:root` tokens; introduce no new hex.

| Role | Value | Usage on this surface |
|------|-------|-----------------------|
| Dominant (60%) | `--drhp-bg` #16171A (page ink) / `--drhp-surface` #1E2024 (if wrapped in a card) | The strip sits quietly on the page/card ground |
| Secondary (30%) | `--drhp-surface-secondary` #26282D | Only if the strip is rendered as a calm panel (mirroring `.drhp-forecast-tested`); optional — default is a plain muted line, no panel |
| Accent (10%) | `--drhp-accent-link` #E6AC5C | **The report link ONLY.** This is the single accent element on the surface |
| Text — value | `--drhp-text-primary` #ECECEA | Eval numbers (mono) |
| Text — label/provenance/fallback | `--drhp-text-muted` #9A9BA0 | Metric labels, provenance clause, and the missing-data fallback line |
| Destructive | **not applicable** | The honesty invariant FORBIDS red/green/severity color on eval figures. No destructive token appears on this surface |

**Accent reserved for:** the eval **report link** (`view report`), rendered as accent-as-text
(`--drhp-accent-link`, underlined). Accent is NEVER applied to any numeric figure, label, or the
per-IPO line. A `faithfulness 0.31` and a `faithfulness 0.99` are text-primary mono, identical.

> **Surface-2 honesty note (required deviation):** the pre-existing `.m-status` class colors its cell
> in accent amber (`--drhp-accent-link`) — fine for the "Phase 3 / Phase 5" phase labels it holds today,
> but amber on a live eval **number** would read as a verdict/eye-catch and violate the invariant.
> Therefore the three filled eval rows must render their live value via a neutral class
> **`.drhp-eval-live`** (mono, text-primary, tabular-nums, weight 400), NOT `.m-status`. The
> non-eval rows (Extraction F1 → "Phase 3", Forecast coverage → "Phase 5") keep their amber status
> labels untouched. This is the choice most consistent with the locked design system.

## Copywriting Contract

Exact strings. `{…}` are substituted from `eval_summary.json`; every numeric `{x}` is formatted to
**exactly 2 decimals**, or `—` (em dash) when the value is missing/null/NaN (never `0.00`, never a guess).

| Element | Copy |
|---------|------|
| System-level figure (every IPO page) | `Measured across our {corpus.n_questions}-question eval set ({corpus.ipo}, {generated}, judge {judge_model}): faithfulness {aggregate.faithfulness_deepeval} · recall@10 {aggregate.recall_at_10} · citation {aggregate.citation_accuracy}` — followed by the report link |
| Report link (accent) | `view report` → href = the committed report path in `report` (e.g. `eval/reports/2026-07-28-rag-eval.md`, resolved to a reachable URL / GitHub blob). If `report` is absent, **omit the link** — render the figures with no dead link |
| Per-IPO line (only when `per_ipo[this_ipo_id]` exists) | `This IPO's eval (n={per_ipo[id].n}): faithfulness {…faithfulness_deepeval} · recall@10 {…recall_at_10} · citation {…citation_accuracy}` |
| Missing-data fallback (JSON absent/unreadable) | `Eval metrics not yet generated for this release.` — muted, no numbers, no red |
| Missing single metric value | `—` (em dash) |
| Primary CTA | **none** — this is a read-only informational surface; the report link is the only interactive element |
| Destructive confirmation | **none** — no destructive actions on this surface |

**Provenance is mandatory on every displayed figure:** the system-level line always carries
`n`, `corpus.ipo`, `generated` (date), and `judge_model`, plus the report link. Faithfulness is a
DeepEval **LLM-judge** number (reported, not gated) — its judge model is named in the provenance clause,
so it is never presented as a deterministic guarantee. `recall@10` and `citation` are deterministic
span-overlap metrics.

Separator between figures: ` · ` (middle dot, matching the existing methodology / forecast copy grammar).

## Component Contract — Surface 1 (inline eval-figure)

**Where:** `pages/02_snapshot.py`, rendered directly **above the Q&A divider** (immediately before
`render_snapshot_chat(drhp_id)`), and **outside the `record is not None` guard** — like the GMP block —
so the honest figure appears on **every** IPO page even while the snapshot is still precomputing.
Rationale: the eval figures describe the reliability of the very Q&A the user is about to use.

**How it reads data:** a small render module (recommend `ui/eval_inline.py`, exposing
`render_eval_inline(drhp_id)`) reads `eval/reports/eval_summary.json` ONCE via a `.is_file()` guard
(mirror `_card_data_path.is_file()` in `pages/01_methodology.py`) wrapped in try/except (mirror the
`load_snapshot` posture). It imports **NO** agent / model / LLM module and makes **NO** live call —
pinned by an `inspect.getsource` isolation test (mirror 03-06 `test_no_llm_or_qdrant_import`).

**Number formatting:** reuse an `_mc_num(value, nd=2)`-style helper — 2 decimals; NaN / non-numeric → `—`.

**Markup shape (Streamlit sanitizer-safe):** a single muted `<p>` (NOT a bare `<div>` — an empty
`<div>` renders as an empty box) with the report link as an inline `<a>` inside the `<p>` (safe: only
`<div>` nested in `<a>` is stripped, not `<a>` in `<p>`). Each numeric value is wrapped in a
`<span class="drhp-eval-figure">…</span>`. If a bordered card is desired, use
`st.container(border=True, key="drhpcard-eval-inline")` — never a split `<div>` (the Phase 3 white-bar
lesson). Default is a plain muted strip (no border), so the figure stays subordinate to the analytical blocks.

**New CSS classes to add to `app/static/drhplens.css`** (inherited `--drhp-*` tokens only):

| Class | Role |
|-------|------|
| `.drhp-eval-inline` | Wrapper strip — muted paragraph grammar; `font-size:14px; color:var(--drhp-text-muted); line-height:1.6; margin:var(--drhp-space-md) 0` |
| `.drhp-eval-figure` | Inline mono numeric value — `font-family:var(--drhp-font-mono); font-variant-numeric:tabular-nums; color:var(--drhp-text-primary); font-weight:400`. Identical for every value |
| `.drhp-eval-provenance` | (optional) the muted provenance clause if separated from the figure line |
| `.drhp-eval-per-ipo` | The per-IPO sub-line — same grammar as `.drhp-eval-inline`, `margin-top:var(--drhp-space-xs)` |
| `.drhp-eval-report-link` | Accent-as-text link — `color:var(--drhp-accent-link); text-decoration:underline`. The ONE accent element |
| `.drhp-eval-empty` | Missing-data fallback line — reuse `.drhp-not-disclosed` grammar (muted italic), or alias it |
| `.drhp-eval-live` | **Surface 2** methodology status-cell live value — `font-family:var(--drhp-font-mono); font-variant-numeric:tabular-nums; color:var(--drhp-text-primary); font-weight:400`. NOT `.m-status` amber |

## Component Contract — Surface 2 (methodology placeholder rows)

**Where:** `pages/01_methodology.py`, the `_ROWS` eval-metrics table. Keep the table's existing
structure/styling (`.drhp-metrics` / `.m-name` / `.m-how` / `.m-target` / `.m-status`). Replace only
the `reported · Phase 6` status cells with the LIVE values from `eval_summary.json`, wrapped in
`.drhp-eval-live` (text-primary mono, per the honesty note above).

| Row (`m-name`) | `m-how` (update) | `m-target` (keep) | Status → live value |
|----------------|------------------|-------------------|---------------------|
| Faithfulness | `DeepEval · LLM-judge · answer grounded in retrieved context` (was RAGAS — engine switched per design doc) | `≥ 0.95` (reported target, not gated) | `aggregate.faithfulness_deepeval` (2dp) |
| Citation accuracy | `custom · did the cited page contain the claim` (unchanged) | `≥ 0.95 · release gate` | `aggregate.citation_accuracy` (2dp) |
| Context recall@k | `custom span-overlap · k = 5 / 10 / 30` (was RAGAS) | `recall@10 ≥ 0.85 · release gate` | `recall_at_5 / recall_at_10 / recall_at_30` (2dp each, ` / `-joined) |
| Extraction F1 | (unchanged) | `reported` | `Phase 3` — **unchanged, keep `.m-status` amber** |
| Forecast coverage | (unchanged) | `≈ 80%` | `Phase 5` — **unchanged, keep `.m-status` amber** |

Same `.is_file()` + try/except read guard as the model-card block already on this page. If
`eval_summary.json` is absent, the three eval rows fall back to their current `reported`/`Phase 6`
status text (never a fabricated number) — no crash.

## Empty / Missing-Data States

| State | Trigger | Render |
|-------|---------|--------|
| JSON absent / unreadable | `eval/reports/eval_summary.json` missing OR `json.loads` raises | Surface 1: single muted line `Eval metrics not yet generated for this release.` (`.drhp-eval-empty`) — no numbers, no red, **page does not crash**. Surface 2: eval rows keep their current `reported`/`Phase 6` text |
| IPO in catalogue but NOT in `per_ipo` | `this_ipo_id not in per_ipo` | System-level figure only. **No per-IPO line.** Never fabricate a per-IPO number |
| Single metric value missing/null/NaN | e.g. `aggregate.recall_at_30 == null` | Render `—` (em dash) for that value only; other figures render normally. Never `0.00`, never a guess |
| `report` field missing | no `report` key | Render the figures **without** the link (never a dead link) |
| `per_ipo[ipo]` present but a metric null | e.g. `per_ipo[ipo].faithfulness_deepeval == null` | That figure → `—`; the rest of the per-IPO line renders |

Read-guard pattern (both surfaces): `_eval_summary_path.is_file()` before read; `try/except` around
`json.loads` → fallback state, never an unhandled exception (mirrors the `_card_data_path` guard and the
`load_snapshot` try/except posture already in the codebase).

## Honesty-Invariant Acceptance Checks

Explicit, testable. The gsd-eval-review + gsd-ui-review gates assert these.

- [ ] **No verdict styling.** No CSS class, inline style, or emoji on any eval figure encodes red/green
      or pass/fail (grep the eval markup: no `green`/`red`/`success`/`danger`/`badge`/`severity` classes,
      no `✅`/`❌`/`⚠️`, no up/down arrow). Refuse the surface if any appear.
- [ ] **Value-invariant styling.** An eval figure renders in the SAME class/style regardless of value.
      Test: render `eval_summary.json` with high (`0.99`) vs low (`0.31`) figures and assert the emitted
      markup is byte-identical except the digits.
- [ ] **Provenance always present.** Every displayed figure is accompanied by `n`, `ipo`, `generated`
      date, and `judge_model`, plus a report link (when `report` present).
- [ ] **No fabricated per-IPO number.** For a catalogue IPO absent from `per_ipo`, assert the rendered
      output contains no `This IPO's eval` substring and no per-IPO figures.
- [ ] **Read-only isolation.** The render module reads ONLY the committed `eval_summary.json` — no import
      of the agent / model / LLM client, no live call at render. Pinned by an `inspect.getsource`
      no-client substring gate (mirror `test_no_llm_or_qdrant_import`).
- [ ] **Accent reserved for the link.** Accent amber (`--drhp-accent-link`) appears ONLY on the report
      link — never on a numeric figure, label, or the per-IPO line. Surface-2 live values use
      `.drhp-eval-live` (text-primary), never `.m-status` amber.
- [ ] **Formatting.** Every figure is exactly 2 decimals; missing/null/NaN → `—` (em dash), never `0.00`.
- [ ] **Faithfulness labelled judge-based.** The LLM-judge faithfulness figure always names its judge
      model in the provenance clause (reported, not gated) — never shown as a deterministic guarantee.
- [ ] **Graceful absence.** With `eval_summary.json` absent, both surfaces render their honest fallback
      and neither page crashes.

## Streamlit-Specific Constraints (baked-in gotchas)

- CSS is injected every run via `load_global_css` (vanishes after `st.rerun()`) — the component adds no
  inline `<style>`; all classes live in `app/static/drhplens.css` (FLAG-2).
- `st.markdown('<div>…')` alone renders an EMPTY box (sanitizer auto-closes) — use a `<p>` with text
  content, or `st.container(border=True, key="drhpcard-eval-inline")` for a bordered card. Never a split `<div>`.
- The sanitizer STRIPS `<div>` nested inside `<a>` — the report link is an inline `<a>` inside a `<p>`
  (safe). If a whole card must be a link, use `<span>` children, not `<div>`.
- Inline SVG survives the sanitizer (not needed here — this surface uses no icons).
- Restore the icon font on `[data-testid="stIconMaterial"]` (already handled globally).
- No live LLM-judge call at render — read the committed JSON only (P19, demo-safe, zero per-view cost).
