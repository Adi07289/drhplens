## Honesty-Invariant Verdict (governing constraint)

All 9 invariant acceptance checks **PASS** in the actual code — verified independently, not from the SUMMARY:

- **No verdict styling** — emitted markup carries only the 5 neutral `.drhp-eval-*` classes; `test_no_verdict_or_severity_markup` scans every `class="…"` against an allowlist and rejects `style=`, emoji, and arrows. Grep of `ui/eval_inline.py` finds `green/red/badge/severity` strings only inside the honesty docstring, never in emitted HTML.
- **Value-invariant** — a `0.99` and a `0.31` summary render byte-identically except the digits (`test_value_invariant_styling`); every value flows through one `.drhp-eval-figure` span.
- **Accent reserved for the link** — CSS confirms `--drhp-accent-link` (#E6AC5C) is applied at exactly one selector, `.drhp-eval-report-link` (line 1709). `.m-status` amber (line 1691) is correctly NOT used for live eval numbers; Surface 2 uses `.drhp-eval-live` text-primary (line 1716).
- **`faithfulness = -1 → "not measured"`** — `_faithfulness_display` maps the `-1.0` sentinel to the words "not measured", never `0.00`/`-1.00` (verified on the committed JSON, which ships `faithfulness_deepeval: -1.0`). This is the CORRECT honest posture and is rewarded, not penalized.
- **Per-IPO line only when present** — renders only for `drhp_id in per_ipo` (committed: `swiggy_2024_11` only); `test_no_fabricated_per_ipo_line` pins the absence for any other IPO.
- **Provenance mandatory** — the system line always carries n, ipo, generated date, and judge model, with the judge named *before* the faithfulness figure.
- **2-decimal / em-dash** — `_eval_num` returns `—` for None/NaN, never `0.00`.
- **Read-only isolation** — imports only `json/pathlib/html/streamlit`; AST allowlist + `inspect.getsource` forbidden-token scan pin it (no live judge/agent call at render).
- **Graceful absence** — `.is_file()` + try/except → single muted `.drhp-eval-empty` fallback; neither page crashes.

The implementation's deliberate restraint (withholding faithfulness as "not measured", plain neutral figures) is the correct compliance posture — it is scored as a strength, not a deficiency.

## Top Priority Fixes

1. **[WARNING · Experience Design] The `view report` accent link is a dead link.**
   *Impact:* the surface's single interactive element — and its only accent — leads nowhere. `render_eval_inline` sets `href` to the raw repo-relative `report` value (`eval/reports/2026-07-29-rag-eval.md`, `ui/eval_inline.py:121-126`). Streamlit does not serve arbitrary repo paths: `.streamlit/config.toml` has no `[server] enableStaticServing`, and even with it, only `static/` is served at `/app/static/…`, never `/eval/reports/…`. The contract (Copywriting Contract, Surface-1 link row) explicitly required the href be "resolved to a reachable URL / GitHub blob … never a dead link."
   *Fix:* resolve `report` to a reachable URL before use — e.g. `https://github.com/<owner>/drhplens/blob/main/{report}` — or copy the report under a served `static/` path and link that; if neither is available, omit the link (the code already omits when `report` is falsy).

2. **[WARNING · Copywriting] "13-question eval set" over-states the measured base.**
   *Impact:* on an honesty-first surface, the provenance verb "Measured across our 13-question eval set" attaches to 13, but the deterministic metrics are computed over 11 grounded questions (2 refusal-eligible questions are excluded — EVAL-REVIEW remediation #10). The corpus size (13) is honest, but "measured across 13" is imprecise about what was scored.
   *Fix:* surface the scored count explicitly (e.g. "13-question set · 11 scored") or reconcile `corpus.n_questions` semantics so the "measured across {n}" clause reflects the scored n.

3. **[Minor · Visuals / Experience] Strip has no wayfinding anchor + read-time schema is `.get()`-defensive, not validated.**
   *Impact:* the strip sits between the muted GMP block and the divider with no eyebrow/heading, so on a long snapshot page two consecutive muted strips can blur together (the contract permits omitting the optional `EVAL` eyebrow, so this is a trade-off, not a breach). Separately, the render uses defensive `.get()` fallbacks rather than an `EvalSummary` re-validation (EVAL-REVIEW #7), so a malformed artifact could partially render instead of failing closed to the empty state.
   *Fix:* consider the optional `.drhp-forecast-tested-eyebrow`-grammar "EVAL" mono eyebrow for scannability, and validate the JSON against the `EvalSummary` Pydantic schema at read time (fail-closed → `.drhp-eval-empty`).

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- **PASS** — System-level copy matches the contract verbatim: `Measured across our {n}-question eval set ({ipo}, {generated}, judge {judge_model}): faithfulness … · recall@10 … · citation …` (`ui/eval_inline.py:113-117, 71-78`), ` · ` middle-dot separator, `view report` link text, and the exact missing-data fallback `Eval metrics not yet generated for this release.` (`:40`).
- **PASS** — Honest sentinel handling: `faithfulness_deepeval == -1.0` renders the words "not measured" (`:52-63`); missing/NaN metrics render `—` (`:43-49`), never `0.00`. Correct per the governing constraint.
- **WARNING** — `13-question` vs 11 scored (see Top Fix #2). Minor honesty-precision gap on a surface whose whole purpose is honest provenance.
- **NOTE (not a defect)** — the per-IPO `(n=…)` clause is omitted when `per_ipo[id]` lacks an `n` key (committed data has none) rather than fabricated (`:139-141`). Correct honest handling of a contract-copy assumption the schema doesn't define; but it means the per-IPO line currently carries no n-provenance of its own.

### Pillar 2: Visuals (4/4)
- **PASS** — Deliberately subordinate: a single muted `<p>` with no heading, sitting under the page `h1` (contract: "subordinate strip"). Hierarchy is created purely by typography/color — text-primary mono figures and prose labels against muted ground, with one amber link — exactly the invariant's mandated "structure/typography/orientation only" eye-catch.
- **PASS** — Streamlit sanitizer gotchas handled: text-bearing `<p>` (not an empty `<div>` box), report `<a>` inline inside the `<p>` (not `<div>`-in-`<a>`), no split card. No icons emitted (an eval severity icon would breach the invariant).
- **Minor** — no visual demarcation between this strip and the adjacent muted GMP block (see Top Fix #3); permitted by contract (eyebrow optional).

### Pillar 3: Color (4/4)
- **PASS** — `--drhp-accent-link` amber appears at exactly ONE selector, `.drhp-eval-report-link` (`drhplens.css:1709`). No figure, label, provenance clause, or per-IPO line is amber.
- **PASS** — Surface-2 required deviation implemented correctly: the three live eval cells wrap their value in `.drhp-eval-live` (text-primary mono, `:1716-1720`); the `<td class="m-status">` amber (`:1691`) is overridden by the inner span, so live numbers read neutral while the non-eval Phase 3 / Phase 5 rows keep amber. Verified in `pages/01_methodology.py:117-134`.
- **PASS** — No red/green/success/danger anywhere; no hardcoded hex/`rgb()` in the eval CSS block (tokens only) or in `ui/eval_inline.py`.

### Pillar 4: Typography (4/4)
- **PASS** — `.drhp-eval-figure`: `--drhp-font-mono`, `tabular-nums`, text-primary, weight 400 — identical for every value (`:1701-1704`). Prose in `.drhp-eval-inline`/`.drhp-eval-per-ipo` is 14px/1.6 muted (`:1697-1708`). Two weights only. Matches the Typography table row-for-row.
- **PASS** — Surface-2 `.drhp-eval-live` at 12px mono fits the "12–14px" methodology-cell spec.
- **NOTE (defensible)** — the words "not measured" render inside the mono `.drhp-eval-figure` span (prose in a numeric style). Slightly unusual, but it is the choice that preserves byte-identical value-invariance, so it is correct for the invariant rather than a typography defect.

### Pillar 5: Spacing (4/4)
- **PASS** — `.drhp-eval-inline` / `.drhp-eval-empty` use `margin: var(--drhp-space-md) 0` (16px); `.drhp-eval-per-ipo` uses `margin-top: var(--drhp-space-xs)` (4px) — the exact tokens the Spacing Scale assigns to "vertical rhythm above/below the strip" and "gap between the system-level and per-IPO sub-line." No arbitrary `[…px]` values in the eval CSS.
- **NOTE** — the report link is separated by a plain word-space rather than an explicit 8px inline gap; this matches the contract's endorsed ` · ` copy grammar, so it is consistent, not a deviation. The pre-existing 48px (`2xl`) Q&A divider is untouched.

### Pillar 6: Experience Design (3/4)
- **PASS** — State coverage is complete and test-pinned (13 tests): absent JSON, unreadable JSON, missing single metric (`—`), missing `report` (omit link), IPO absent from `per_ipo` (no line), committed-artifact render. `.is_file()` + try/except guarantees no crash (`:88-101`).
- **PASS** — Rendered outside the `record is not None` guard, above the Q&A divider (`pages/02_snapshot.py:407-413`), so the reliability figure appears on every IPO page even mid-precompute — matching the contract's placement rationale.
- **PASS** — Read-only isolation (P19): imports only `json/pathlib/html/streamlit`, no live judge/agent call, AST-allowlist + `inspect.getsource` pinned. Every interpolated value HTML-escaped; href escaped with `quote=True` (T-6.1-19 XSS).
- **WARNING** — dead `view report` link (see Top Fix #1). The one interactive/accent element is non-functional as shipped; it does not crash or block the read-only figures (primary task intact), hence a WARNING and a 3, not a BLOCKER.
- **Minor** — read-time validation is defensive `.get()` rather than `EvalSummary` re-validation (fail-open on a malformed artifact; EVAL-REVIEW #7).
