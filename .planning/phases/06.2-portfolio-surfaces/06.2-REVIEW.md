# Phase 06.2: Code Review Report

**Reviewed:** 2026-08-02T00:00:00Z
**Depth:** standard
**Files Reviewed:** 15
**Status:** issues_found

## Summary

Reviewed the three new Phase 6.2 recruiter-facing surfaces (`/failures` gallery, the
`/methodology` architecture hero + model card, and the committed eval dashboard
generator) plus their supporting chrome, copy, CSS, data and tests. The
render-only/demo-safe posture (P19) holds up under direct inspection: `ui/failures.py`
really does import only the documented allowlist, `yaml.safe_load` is used (never the
unsafe loader), every interpolated field is `html.escape`d before
`unsafe_allow_html=True` markup, and the committed dashboard genuinely contains zero
`http(s)://` asset references. The honesty invariant (neutral open/mitigated, no
red/green, Swiggy-only per-IPO framing, faithfulness `-1.0` → "not measured") is
correctly implemented in the paths that are actually exercised by the current
committed data.

The review did find one real BLOCKER: a `st.stop()` inside the `/methodology`
model-card's corrupt-JSON fallback silently truncates the *entire rest of the page*
(Guardrails, Stack, "Show your work" CTA, and the site footer all disappear) instead
of degrading just the model-card section as the surrounding comment claims. This path
is untested and would only fire if `model_card/card_data.json` becomes corrupt/
unreadable, but given it's on the phase's flagship recruiter-facing page, it's worth
fixing before it can bite in production. Three further WARNING-level robustness gaps
sit in the same "degrade gracefully, never crash" family (unvalidated YAML list
elements in `ui/failures.py`, a type-fragile `-1.0` sentinel check on
`/methodology`, and unguarded `None` defaults in the model-card JSON reads) — all
currently unreachable with the committed artifacts but latent given how easily a
hand-edited data file could trip them.

## Critical Issues

### CR-01: `st.stop()` in the model-card corrupt-JSON handler aborts the rest of the `/methodology` page

**File:** `pages/01_methodology.py:239-247`
**Issue:** When `model_card/card_data.json` exists but fails to parse (`json.loads`
raises `ValueError`/`OSError`), the `except` branch renders a one-line fallback
message and then calls `st.stop()`. `st.stop()` halts the *entire* Streamlit script
run — not just the model-card block. Everything that follows in the file never
renders for that page load: the "Guardrails" section (`render_section_head`, line
393), the "Stack" chip list (line 411), the "See the work on every answer" CTA band
(line 419), and — critically — `render_site_footer()` (line 431), which is the only
place the compliance disclaimer ("Not a SEBI-registered investment adviser…") is
emitted on this page. The inline comment directly above this code
(`# corrupt/unreadable card degrades to the same fallback, never crashes (WR-05)`)
describes intended behaviour that the code does not actually implement — it doesn't
crash, but it does silently drop most of the page, including the compliance footer,
with no test covering this path (`grep -rn "corrupt" tests/unit/*.py` shows no test
exercises this branch of `pages/01_methodology.py`). `st.stop()` is not used anywhere
else in `pages/` or `ui/`, so this isn't an established pattern being followed
elsewhere either.
**Fix:** Don't halt the script; just skip the model-card body and let the rest of the
page render normally.
```python
_card = None
if not _card_data_path.is_file():
    st.markdown(
        '<p class="drhp-method-note drhp-not-disclosed">'
        "The forecaster model card has not been generated yet.</p>",
        unsafe_allow_html=True,
    )
else:
    try:
        _card = json.loads(_card_data_path.read_text(encoding="utf-8"))
    except (ValueError, OSError):
        st.markdown(
            '<p class="drhp-method-note drhp-not-disclosed">'
            "The forecaster model card could not be read (corrupt artifact).</p>",
            unsafe_allow_html=True,
        )
        _card = None

if _card is not None:
    ...  # existing model-card body (seed note, coverage/MAE/R2, plots, DM table,
         # leakage/anchor audits, sector table, limitations grid) — unchanged, just
         # no longer gated behind st.stop()
```

## Warnings

### WR-01: `ui/failures.py` will crash instead of showing the empty-state on a malformed (non-mapping) YAML entry

**File:** `ui/failures.py:122-158`
**Issue:** After the top-level `isinstance(entries, list)` check (line 131), nothing
validates that every *element* of the list is itself a mapping before the code calls
`.get(...)` on it — in the surface filter (line 137: `e.get("surface")`), the
free-text filter (line 142: `e.get(k, "")`), the sort key (line 150:
`e.get("surface", "")`), and the render loop (`entry.get(...)` throughout
`_card_html` and line 157's container `key=`). A committed `failures.yaml` with a
blank list item (`- \n` — a common YAML authoring slip) or a bare string entry
parses successfully as `[None, ...]` / `["a string", ...]` under
`yaml.safe_load` and passes the `isinstance(entries, list) and entries` guard, then
raises `AttributeError: 'NoneType'/'str' object has no attribute 'get'` on the very
next line — an uncaught exception that crashes the page. This directly contradicts
the module's own documented invariant: "an absent / unreadable / empty file, or a
no-match search, renders ONE muted empty-state `<p>`, never a crash." The current
committed `eval/failures/failures.yaml` is schema-tested and clean, so this is not
reachable today, but the data file is explicitly hand-curated (not machine-generated)
and not scrubbed, so a future edit slipping past review is a real risk.
**Fix:**
```python
if not isinstance(entries, list) or not entries:
    _empty_state()
    return
entries = [e for e in entries if isinstance(e, dict)]
if not entries:
    _empty_state()
    return
```

### WR-02: `/methodology` faithfulness sentinel check compares the raw value instead of the float-cast value

**File:** `pages/01_methodology.py:130-132`
**Issue:**
```python
_faith_raw = _eval_agg.get("faithfulness_deepeval")
_faith_txt = "not measured" if _faith_raw in (-1, -1.0) else _mc_num(_faith_raw, 2)
```
This checks membership on the *raw* JSON value before any type coercion. With the
currently-committed `eval_summary.json` (`faithfulness_deepeval` is a JSON number,
parsed as Python `float(-1.0)`) this works. But the sibling implementation of the
exact same rule in `scripts/build_eval_dashboard.py::_faith` deliberately casts to
`float()` *first* and then compares (`num == _NOT_MEASURED`), specifically so a
differently-typed sentinel (e.g. a stringified `"-1.0"`, an `int` written as `-1`
some other way, etc.) is still caught. Here, a non-`float`/`int` representation of
the sentinel would fall through to `_mc_num(_faith_raw, 2)`, which itself does
`float(value)` and would print the fabricated-looking figure `-1.00` on the live
metrics table instead of the honestly-required "not measured" — the exact failure
mode the sentinel rule exists to prevent. Two independently-maintained
re-implementations of the same honesty rule silently drifting in robustness is a
real regression risk (the next person changes one and not the other).
**Fix:** Cast before comparing, matching `scripts/build_eval_dashboard.py::_faith`:
```python
def _is_not_measured(raw) -> bool:
    try:
        return float(raw) == -1.0
    except (TypeError, ValueError):
        return False

_faith_txt = "not measured" if _is_not_measured(_faith_raw) else _mc_num(_faith_raw, 2)
```

### WR-03: Model-card JSON reads use `.get(key, default)`, which doesn't protect against an explicit `null`

**File:** `pages/01_methodology.py:294, 309, 313, 352, 369, 385`
**Issue:** `dict.get(key, default)` only returns `default` when `key` is *absent* —
if the committed JSON has `"leakage_audit": null` (or any of `baselines`,
`anchor_audit`, `n_per_sector`, `limitations`), `.get(key, [])` / `.get(key, {})`
returns `None`, not the fallback. Line 309's `_leak = _card.get("leakage_audit", [])`
feeds directly into `any("populated_live" in r for r in _leak)` at line 313 — if
`_leak` is `None`, this raises `TypeError: 'NoneType' object is not iterable`,
crashing the page with no surrounding `try`/`except` (the only `try` in this section
wraps just the `json.loads` call at line 240). The same pattern repeats for
`baselines` (line 294), `anchor_audit` (line 352), `n_per_sector` (line 369) and
`limitations` (line 385). This is the same class of gap as WR-01/CR-01 — the file's
stated design intent is "a corrupt/unreadable artifact degrades to no note, never
crashes the page (WR-05)", but a *structurally valid* JSON with a null field for any
of these keys is not covered by that guard.
**Fix:** Use `or` to normalize `None` to the empty fallback, e.g.:
```python
_leak = _card.get("leakage_audit") or []
...
for b in (_card.get("baselines") or [])
...
for r in (_card.get("anchor_audit") or [])
...
for _sector, _n in sorted((_card.get("n_per_sector") or {}).items())
...
for _lim in (_card.get("limitations") or [])
```

### IN-02: `html.escape()` used to build a non-HTML Streamlit widget key

**File:** `ui/failures.py:157`
**Issue:** `key=f"drhpcard-fail-{html.escape(str(entry.get('id', '')))}"` HTML-escapes
the failure `id` to build a `st.container(key=...)` value. `key=` is an internal
Streamlit widget identifier, not rendered as HTML, so escaping here is the wrong tool
for the job — it's harmless with the current simple slug-style ids (no `&`, `<`, `>`,
`"` characters) but is a confusing pattern that doesn't actually protect against key
collisions (e.g. two ids that only differ by characters `html.escape` treats
identically would still collide).
**Fix:** Use the raw id (or `re.sub` to a safe key charset) rather than
`html.escape`, e.g. `key=f"drhpcard-fail-{entry.get('id', '')}"`.

### IN-03: `ui/failures.py`'s documented import allowlist and its pinning test's allowlist have drifted

**File:** `ui/failures.py:5-6`, `tests/unit/test_failures.py:125`
**Issue:** The module docstring states the read-only allowlist is `{__future__,
html, pathlib, yaml, streamlit}` (5 modules — `ui/failures.py` does not import
`json`). The pinning test's `allowed` set is `{"__future__", "html", "json",
"pathlib", "yaml", "streamlit"}` (6 modules, including `json`, which the module
never imports). This is harmless today (a permissive allowlist can't cause a false
failure), but the two "source of truth" descriptions of the same invariant disagree,
which is confusing for the next maintainer following either one.
**Fix:** Drop `"json"` from the test's `allowed` set to match the module docstring
(or explicitly note in both places why `json` is pre-allowed for a future change).
