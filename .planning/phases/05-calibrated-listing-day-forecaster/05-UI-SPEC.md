## Discretion Resolved (prescriptive rendering decisions inside the locked frame)

The four visual decisions are locked. The micro-rendering decisions the executor needs — band geometry, axis-domain math, marker forms, metrics-strip layout — are Claude's discretion and are resolved here, **prescriptively** (executor implements without ambiguity).

### D-1 — Axis domain + marker positioning math (deterministic, so every IPO renders consistently)

The return axis is a linear `listing-day return %` scale. Compute the visible domain from the record so the band, median, 0%, and GMP marker always fit with breathing room:

1. Anchor set `A = { 0, interval_low, interval_high, median } ∪ ({ gmp_implied } if GMP present)`.
2. `raw_min = min(A)`, `raw_max = max(A)`.
3. `pad = max(2.0, 0.08 × (raw_max − raw_min))`.
4. `domain_lo = floor_to_5(raw_min − pad)`, `domain_hi = ceil_to_5(raw_max + pad)` (round outward to the nearest 5 points; `0` is always inside since it is an anchor).
5. For any value `v`: `left% = clamp( (v − domain_lo) / (domain_hi − domain_lo) × 100, 0, 100 )`.
6. **Band:** `left% = pos(interval_low)`; `width% = pos(interval_high) − pos(interval_low)`. The band width is the dominant visual; it is never allowed to render below a **4px** minimum visual width even when the interval is unusually tight (a floor so a genuinely tiny interval is still visible; the caption still states the true span).

Axis-end labels print `domain_lo%` (left) and `domain_hi%` (right); the `0%` label sits at `pos(0)`. All positions are inline `left:%` on absolutely-positioned children of the axis track (single self-contained `st.markdown`).

### D-2 — Element forms (distinguishable by SHAPE, never by colour alone — WCAG 1.4.1)

Four elements share the axis; each has a **distinct form** so meaning never rests on colour:

- **Interval band** (`.drhp-forecast-band`): a filled horizontal region, **low-opacity amber wash** `rgba(224, 162, 78, 0.16)` with **2px amber edges** `rgba(224, 162, 78, 0.60)` at the interval bounds so the WIDTH reads as the message. `6px` corner radius. ~`28px` tall, vertically centred in the track. This is the ONLY amber element in the section.
- **Median tick** (`.drhp-forecast-median`): a **short, faint, neutral** vertical tick — `2px` wide, ~`60%` of track height (centred), colour `--drhp-text-muted`. Deliberately quiet: it marks the point estimate without becoming one. **No numeric headline** — the value appears only as a Small muted `Model median {z}%` annotation beneath the tick and in the aria-label.
- **0% baseline** (`.drhp-forecast-zero`): a **full-height 1px** vertical rule, colour `--drhp-text-muted`, with a Small muted `0%` label beneath it. Full-height rule vs. short tick makes it unmistakable from the median.
- **GMP marker** (`.drhp-forecast-gmp`): a **hollow outlined diamond** (`12px` square rotated 45°, `1.5px` `--drhp-text-muted` border, transparent fill) on a thin `1px` `--drhp-text-muted` stem — **NEVER amber, NEVER filled**. A hollow diamond vs. the amber wash vs. the neutral bars is a form difference, not a hue difference. Omitted entirely when no GMP is reported (see States).

### D-3 — "How this was tested" honesty-metrics strip (always visible — L5-3, FCAST-04)

A calm `--drhp-surface-secondary` strip (`.drhp-forecast-tested`) directly under the plot, **never collapsed, never behind an expander**:

- A Small mono muted eyebrow: `How this was tested`.
- A three-up stat row (`.drhp-forecast-stat`): **80% interval coverage (empirical)**, **Mean absolute error (MAE)**, and the **backtest window / N**. Each stat = a Body-16 **mono, tabular-nums, weight-400** value (deliberately NOT Display-28, NOT bold — it must not become a headline that competes with the absent point estimate) + a Small muted label.
- A compact **per-year RMSE** mini-table (`.drhp-forecast-rmse`) — rows are `year → RMSE (pts)`, tabular-nums, always visible. This is the FCAST-04 "per-year RMSE, visible to any user" requirement rendered in full, not summarised away.
- A Small muted italic honesty note stating coverage is empirical on held-out data and may miss 80% (P17).
- **No colour on any metric** — a 78% coverage is not red, an 11-point MAE is not amber; they are plain neutral numbers (honesty invariant).

### D-4 — Section framing (mid-page climax, not headline — L5-4)

The section renders in an `st.container(border=True, key="drhpcard-forecast")` card matching the inherited lifted-depth card chrome (`st-key-drhpcard-*`). Heading is the locked serif `.drhp-snapshot-block-heading` line; a Small muted `st.caption` sub-line states the GMP-free + calibrated framing. No Display-size hero, no big number — the **band width** and the **plain-language caption** carry the weight.

## The GMP-implied-return conversion (isolation note — GMP-02 / D4-03 / FCAST-02)

L5-2 requires the GMP marker to sit on the same **return %** axis as the model, so the cached GMP **₹ premium** must be converted to an implied **return %**: `gmp_implied_return_pct = gmp_premium_₹ / issue_price_₹ × 100`, using the upper price-band / issue price already surfaced in the Phase 2 metadata header. **This conversion is a display-layer computation** — it lives with the GMP/display code (reading only the cached `data/gmp/<drhp_id>.json` + the cached issue price), **not** in the forecast model pipeline. The model never consumes GMP (FCAST-02). The marker is therefore a read-only annotation of independently-cached data, exactly like the quiet GMP block — the two GMP surfaces share one cache and one caveat posture. If the issue price needed for the conversion is unavailable, the marker + gap line are omitted (the band still renders) with the honest no-gap note.
