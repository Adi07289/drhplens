# Phase 6.2 — Portfolio Surfaces — Design

**Date:** 2026-08-01
**Alias:** 6b
**Branch:** `phase6/6b-portfolio-surfaces` (off `main`, which now contains Phase 5 + 6.1)
**Requirements:** LAND-01, FAILGAL-01, OPS-03 (EVAL-04 already delivered via METHOD-01 — out of scope)
**Depends on:** Phase 6.1 (eval harness + committed `eval_summary.json` + Langfuse ops)

## Goal

Turn the finished, honest eval harness into three recruiter-facing portfolio surfaces so a
hiring manager / DS recruiter can, without running the app, understand the system, see the
rigor, and read the failures — with the project's honesty invariant intact throughout.

## Locked decisions (brainstorm, 2026-08-01)

1. **Failure gallery source** — *curated, committed, render-only.* Author ≥10 REAL documented
   failures into a committed data file; the `/failures` page reads it with no live calls
   (matches the whole codebase's demo-safe posture). NOT live-from-Langfuse.
2. **Recruiter landing lead** — *systems breadth.* The `/methodology` hero leads with the
   end-to-end pipeline (architecture diagram): "A 400-page prospectus, read honestly."
   Rigor + honesty (eval numbers, honest model card, failures) are supporting evidence below.
3. **OPS-03 dashboards** — *one self-contained committed HTML eval dashboard + a strong
   portfolio README.* Not a multi-dashboard generator; not README-only.

- **OPS-02** public deploy (Hugging Face Spaces) — Phase 6.3 (launch gate).

## Surface A — FAILGAL-01: `/failures` gallery

- **Page:** `pages/04_failures.py` (Streamlit multipage; URL `/failures`).
- **Renderer:** `ui/failures.py::render_failures()` — render-only (reads the committed YAML,
  no live calls), HTML-escaped, pinned by a P19 AST-isolation test like `eval_inline`.
- **Data:** committed `eval/failures/failures.yaml`. Per-entry schema:
  `id, surface (exactly one of: rag | extraction | forecast), category (finer bucket —
  e.g. retrieval, parsing, cite, gate1, numeric, refusal, calibration), query, expected, actual,
  postmortem, status (open|mitigated), refs (report/commit paths)`.
  The `surface` field is the 3 top-level buckets the test checks for; the bullet prefixes below
  (parsing/retrieval/cite/gate1/numeric) are `category` values that roll up under `surface: rag`.
- **Content** (authored from REAL, already-documented failures — ≥10, all three top-level surfaces present):
  - forecast: model does **not** beat baselines (the honest P9-fail headline) — *open (by design)*
  - rag: `num-030` — LLM over-answers with numbers not in retrieved context — *open*
  - rag/refusal: `swiggy-012` OOS (Zomato cmp) answered-not-refused → deterministic OOS guard — *mitigated*
  - retrieval: recall saturated at 1.00 on coarse gold spans — a *measurement* limitation, not a win — *open (disclosed)*
  - faithfulness: "not measured" — judge-vs-human calibration not yet done — *open (disclosed)*
  - parsing: 273k-token "Preamble" mega-section → wrong/empty cited windows → page-anchored re-parse — *mitigated*
  - cite: mis-anchored numeric claim → `repair_citations` re-anchors to the chunk that holds the numbers — *mitigated*
  - gate1: bge-reranker negative logits refused answerable DRHP Qs → recalibrated threshold — *mitigated*
  - extraction: F1 misses on specific fields (from the extraction-F1 report) — *open/partial*
  - numeric: `num-033` defective computed-value gold question → reclassified (human-reviewed) — *mitigated*
  - (author to ≥10, ideally 12–15, balanced across surfaces)
- **Honesty:** neutral presentation; `open`/`mitigated` shown truthfully; no green/red gamification;
  a failure is never spun as a success.
- Removes/monitors any stale "failure gallery" placeholder copy in `pages/03_how_it_works.py` /
  `pages/01_methodology.py` that referenced a not-yet-built gallery.

## Surface B — LAND-01: `/methodology` recruiter extension

- **Extends** `pages/01_methodology.py` (the requirement pins the `/methodology` URL — not a new page).
- **New hero (top):** systems-breadth. Headline "A 400-page prospectus, read honestly." + an
  **architecture diagram** of the pipeline. The diagram MUST reflect what actually runs (honesty
  invariant): `DRHP PDF → PyMuPDF + pdfplumber page-anchored parse (NOT Docling — it can't run
  in-env) → bge-m3 embed → Qdrant hybrid (dense+sparse) → bge-reranker-v2-m3 → LangGraph agent
  (gate1 → generate → scrub → cite-check) → Instructor structured extraction → XGBoost + MAPIE
  conformal forecast → cited answer`. Render approach (inline HTML/CSS vs committed SVG) decided
  in `/gsd-ui-phase`.
- **Supporting evidence (mostly already present):** the 6.1 eval numbers, the honest model card
  (forecaster loses to baselines), targets/gates.
- **New additions:** a per-IPO eval summary framed honestly ("1 IPO has a real gold set — Swiggy;
  others show the system-level figure"); a prominent link to `/failures`; a live-demo link
  placeholder (activates in 6.3 / OPS-02).
- Reuses `.drhp-*` classes + `ui/copy.py`.

## Surface C — OPS-03: committed HTML dashboard + README

- **Generator:** `scripts/build_eval_dashboard.py` → committed **self-contained**
  `eval/dashboards/eval-dashboard.html` (no external/CDN deps — inline CSS + inlined plot images).
  Contents: recall@k / citation / faithfulness (from `eval_summary.json`), extraction F1, forecast
  conformal coverage + the calibration plot. Renders on GitHub/locally without the app.
- **README rewrite** (portfolio-grade): the story (honest IPO analyst) → architecture → evals →
  links to the dashboard, model card, `/methodology`, `/failures`, and a live-demo placeholder.
- Optional `make dashboard` target.

## Cross-cutting

- **Data flow:** every surface is render-only from committed artifacts (`failures.yaml`,
  `eval_summary.json`, model card, plots). No live service call at render (P19 / demo-safe).
- **Testing:**
  - `/failures` render test + `failures.yaml` schema+count test (≥10 entries; all of rag /
    extraction / forecast represented; every entry has a non-empty postmortem + valid status).
  - AST-import isolation test for `ui/failures.py` (allowlist: yaml/json/pathlib/html/streamlit).
  - LAND-01 landing-section render test (hero present, `/failures` link present, per-IPO summary honest).
  - `build_eval_dashboard.py` test: dashboard builds, is self-contained (no external URLs), and
    contains the committed numbers from `eval_summary.json` (report/gate can never diverge from the surface).
- **Honesty invariant everywhere:** neutral, truthful `open`/`mitigated`, no gamified verdicts,
  no fabricated per-IPO numbers.

## Success criteria (what must be TRUE)

1. `/failures` renders ≥10 real, honestly-labelled failures across RAG / extraction / forecast from
   a committed file, with category / query / expected-vs-actual / post-mortem, no live calls.
2. `/methodology` opens with a systems-breadth hero (accurate architecture diagram) and links the
   model card, `/failures`, and a per-IPO eval summary — extending, not replacing, the existing page.
3. A self-contained `eval-dashboard.html` is committed and renders the eval numbers off-app; the
   README is portfolio-grade and cross-links every surface.
4. Everything render-only + honesty-invariant; tests pin schema, isolation, and report/surface parity.
